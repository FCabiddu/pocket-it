# Lessons — method, independent of the stack

The third layer of memory. Project truths live in each project's facts (read via `handoff.sh facts`); stack rules live in each project's `best-practices/`; **this file holds what we learned about how to work**, valid on every project. Read at Step 0 by developer, qa-engineer, reviewer and implementation-planner, together with the shared rules. Written by `retro` (a PR on this repo that it merges itself — text only) and by humans.

Rules of the file: one lesson = one line, in the fixed form below; ≤ 40 lessons; a lesson enters as `provisional` and becomes `confirmed` when a later retro sees it hold on a second project or epic, or is removed if it does not; a `confirmed` lesson that keeps mattering is promoted to a rule in `implementing-common.md` / the orchestrator's CLAUDE.md and deleted from here. Nothing in this file names a client or a project — write "project A".

Form: `- {date} · {status} · WHEN {situation} · DO {action} · BECAUSE {evidence, one clause}`

## Lessons

- 2026-09-09 · confirmed · WHEN a task's criterion is "make the suite pass" or "fix the reds" · DO not split it and give it a custom budget · BECAUSE the work is only discoverable by running the whole thing (project A: 249 turns, interrupted at 120 for nothing)
- 2026-09-09 · confirmed · WHEN an agent runs over its budget · DO check progress, not size: stop only if 20 minutes of wall clock brought no commit and no new green test · BECAUSE a hard cap interrupts productive work and a stall wastes the run regardless of the cap
- 2026-09-09 · confirmed · WHEN backend and frontend of one story would otherwise be sequential · DO write a contract task first (types, schema, OpenAPI fragment) and put both sides in the same wave · BECAUSE every story waited a full wave for its endpoint
- 2026-09-09 · confirmed · WHEN a reviewer makes the same finding twice · DO write it as a project fact (and the retro decides if it is a rule) · BECAUSE nine good facts sat unread in project A until agents were told to read them at Step 0
- 2026-09-09 · confirmed · WHEN working inside an isolated worktree · DO use repo-relative paths only, never a path into the main checkout · BECAUSE the harness blocks each such command and every block costs a turn (34 in one session)
- 2026-09-09 · confirmed · WHEN no named agent seems to fit a piece of work · DO stop and name the missing agent, never launch `general-purpose` · BECAUSE it has no rules, no budget, no read discipline (one reached 414k of context)
- 2026-09-09 · confirmed · WHEN a session has closed two waves · DO keep the orchestrator thin instead of holding the work — compaction is automatic (`autoCompactWindow`), nobody has to trigger it, and state lives on disk — so the main session reads only 8-line reports, never diffs, task files or review comments · BECAUSE the orchestrator's context, not the agents', was 73 % of the audited bill
- 2026-09-09 · confirmed · WHEN a review is about to start · DO run the mechanical checks first and reject red PRs without reading — unless the red comes from the harness itself, which is diagnosed, not obeyed · BECAUSE it held on project B too (rework 11 % over 74 PRs), and there a false RED from an unquoted path would have bounced a green PR
- 2026-09-09 · confirmed · WHEN a product is developed over many features · DO keep one project document and write a delta per feature, for BAD and TAD alike · BECAUSE project A accumulated 8 TADs and 9 IPDs repeating the same stack, while project B at epic 27 has one root best-practices file plus a delta per feature and never repeats it
- 2026-09-09 · provisional · WHEN work has been accumulating on a branch with no task file · DO stop and write the task file before the next commit · BECAUSE three weeks and 23 commits arrived as one 96-file review holding ten unrelated features, with stated acceptance criteria for about 20 % of it
- 2026-09-09 · provisional · WHEN a pipeline default changes · DO re-read the per-project config at session start and let it win · BECAUSE a project pinned `automerge: false` the day before the default flipped to true, and reviewer and orchestrator then disagreed about who merges
- 2026-09-09 · provisional · WHEN deciding that a branch is merged · DO ask for its PR state, never infer from ancestry or from the remote branch being gone · BECAUSE squash-merge rewrites the sha and leaves the branch on origin: cleanup recognised 0 of 100 branches that a manual pass then deleted
- 2026-09-09 · provisional · WHEN a task file is written · DO always give it a `**Status**` line · BECAUSE a file without one is invisible to the wave picker but counted as open by the index — 56 such files in project B, and six of them would have been launched as Todo
- 2026-09-09 · confirmed · WHEN a reviewer is about to APPROVE citing tests as evidence · DO count only tests it watched run green in this review, and for a changed shared value (token, constant, schema) run every test that reads it · BECAUSE an audit of 3 first-round approvals on project A found 2 merged with red tests the PR body called green, one a live AA regression the repo already had a test for
- 2026-09-11 · confirmed · WHEN a test is offered as proof that a criterion holds · DO run the mutation that should turn it red and paste the output; a test whose mutation stays green proves nothing · BECAUSE one epic on project A produced five green suites over broken code (a matcher that ignores the ARIA attribute it was asserting, a simulator that does not implement the behaviour under test, six state attributes nailed to a constant with 213 tests green, a dedup deleted at the call site with all seven of its unit tests green)
- 2026-09-11 · provisional · WHEN the affected-test command reports "no test files found" for a file the change is about · DO treat it as a red: the only new behaviour is unproven · BECAUSE on project A inverting the single new gate left the whole suite green, and the PR came back for a full review round
- 2026-09-11 · provisional · WHEN a number appears in a report, a PR body or an acceptance criterion · DO produce it with the tool that owns it, from the main checkout, and name the tool · BECAUSE in one day on project A a search command used as a proxy for the test runner was wrong by the very bug it was measuring, the runner's own config was collecting the agents' worktrees (25016 files against 229), two "equivalent" listers disagreed because one stops silently on the first unparsable file, and a size task was declared done without a single byte measured
- 2026-09-11 · confirmed · WHEN a mechanical check goes red on a file the change never touched, or a lockfile-tracked dependency bump has just merged · DO diagnose the environment or the base first — installed tree against the lockfile, a clean reinstall, or the same check re-run against a clean checkout of the base branch's own tip — reinstall the shared checkout right after such a merge instead of waiting for a red to reveal the drift — and never edit the source a false result points at, never label it the PR's own rework · BECAUSE one mismatched install fooled three agents on project A into a source change that would have broken the build once dependencies were right; on project D the same shape held with a different technique — a shared log line malformed on the base broke an unrelated PR's own self-check, and re-running that check against a clean base tip (not a source edit) named it correctly as inherited, not introduced; and on project A again the drift produced no red at all — two days of tests and the verify step ran green against a dependency version the lockfile no longer declared, caught only when a reviewer's own throwaway clean install disagreed with the shared checkout
- 2026-09-11 · provisional · WHEN agents must append to one shared narrative file during a parallel wave · DO keep it off the feature branches: each branch writes its own fragment and the file is composed when read — never merged by a closing step, rotated by size or reconciled by hand · BECAUSE a union merge driver resolves the conflict locally but is not applied by the host's merge, a day of chained conflicts on project A cost a dedicated agent, and on a second day a hand reconciliation plus a size-based rotation silently moved eight facts out of the section agents read at start, two of them already archived
- 2026-09-11 · provisional · WHEN two agents disagree on a number or on what a red means · DO have each re-execute the other's measurement instead of arguing from the reports · BECAUSE four such disagreements in one epic were settled that way, with either side right about half the time, and each produced a durable fact
- 2026-09-11 · confirmed · WHEN a rule asks an agent to self-report an exception (budget overrun, stall, deviation) · DO derive it from the transcript instead, and treat its absence as missing instrumentation, not as absence of the problem · BECAUSE across three months and two projects not one BUDGET or STALL line was ever written, while the usage report showed ten agents past 150 turns in a single epic; and once the line was finally written, two of four over-budget agents reported being within budget at about half their real turn count
- 2026-09-11 · provisional · WHEN a tooling bug in this repo is found while working on a project · DO write the diagnosis from its mechanism alone — failing line, triggering input shape, expected behaviour — and strip every project name, path, id and narration from the task, the report, the commit and the PR body; the launch prompt carrying that context is not permission to repeat it
- 2026-09-12 · provisional · WHEN two PRs of the same wave are each green on their own branch · DO before approving the second, merge them in the planned order in a throwaway worktree and run typecheck, lint and the full unit suite on the result · BECAUSE in one day on project A git reported no conflict twice while the merged tree held three reds and one test passing vacuously on an empty DOM (a shared test helper turned async in one PR, a default locale changed under the other), and the linter's floating-promise rule flags the un-awaited call in seconds
- 2026-09-12 · confirmed · WHEN a report concludes that an effect is absent (no gain, already handled, already correct, within budget) · DO measure it where the effect is expected and everywhere it applies, and write into shared memory only what was measured · BECAUSE on project A a bundle task measured the one page where no gain was possible, called the gain nil and wrote a false bundler fact into the memory, and the reviewer measured the other page and found −6 %; on project C "the rest were already correct", written over 43 classified exit points of one script, was false at three of them, and a reviewer who ran 3 of those rows instead of reading them found it
- 2026-09-12 · provisional · WHEN a bug task names the files where an intermittent failure shows · DO reproduce the triggering condition before editing them, and let a reproduced cause outside those files override the file list · BECAUSE on project A a flaky database suite was a cross-process deadlock (solo runs 5 of 5 green, concurrent pairs 7 of 8 deadlocked), not a defect in the three named files, and the deviation closed the cause under budget
- 2026-09-12 · provisional · WHEN one reviewer would be launched for a whole wave · DO give each reviewer about three PRs and launch disjoint reviewers beyond that · BECAUSE on project A a seven-PR review exhausted a 60-turn reviewer, at about twenty turns per PR once merged-tree runs and re-executed mutations are counted
- 2026-09-12 · provisional · WHEN estimating a change to a default or a shared helper that tests consume · DO count the consuming test files first and, beyond about ten, split their migration into its own task in the same wave · BECAUSE on project A such a change sized medium migrated nineteen test files and took more than twice its budget, stopping once at the turn limit
- 2026-09-13 · confirmed · WHEN a behaviour covers a class of cases (command shapes, argument grammars, id shapes, category definitions, printed commands) · DO write the class's dimensions and a table of cases into the criteria from the start, and generate the test from the same declaration that defines the behaviour (the full alias list, the per-subcommand argument declaration, every printed command executed on names with shell-special characters) · BECAUSE on project C 16 NEEDS WORK in two days across ten PRs were "examples instead of the class" (rounds of 7, 7, 5, 4), each round closing the cases it was shown, and every one converged only once the test was derived from the declaration; the same shape had already cost a round on project A
- 2026-09-13 · provisional · WHEN a reviewer prescribes a correction inside a finding · DO run it and then check its result against every invariant the task states, not only against the finding it closes · BECAUSE on project C a prescribed recovery closed its finding and republished history a deliberate rewrite existed to remove, twice in a row (first on the base, then under a new branch name), and a prescribed definition made an ordinary test forbidden; the round whose text was checked against the task's invariants converged
- 2026-09-13 · provisional · WHEN writing a launch or resume prompt · DO state each invariant as the damage it prevents ("nothing written to any remote under any name"), never as the place it was seen ("not on the base"); never ask for an outcome ("bring it back to green") that can only be reached by breaking one; and when one rule spans two PRs, define its terms once under a heading the other cites by name · BECAUSE on project C a place-shaped invariant was satisfied by a rescue branch that republished removed history, an outcome-shaped request produced a command that wrote to the base, and two PRs defining the same terms separately collided until one cited the other's heading
- 2026-09-13 · provisional · WHEN a task builds a guard or a check · DO state at its top what it protects against and what it deliberately does not, and review bypasses against that model only · BECAUSE on project C a guard reframed in its second round to a cooperative-agent model closed in four rounds, while a guard with no stated model was cancelled after three rounds, each finding a new shell form that executes text
- 2026-09-13 · confirmed · WHEN a developer would be resumed for yet another review round on the same PR · DO launch a fresh one on the existing branch from the third round on — the branch, the PR comments and the resume report carry the state · BECAUSE a resumed agent re-reads its whole transcript on every call: one two-day usage report showed eight developers past 300k context, the largest 487k over 705 calls
- 2026-09-15 · provisional · WHEN a test is generated from the same declaration the code under test uses, or its oracle is an external document · DO take the case list from the declaration but the expected values from an independent oracle, extracted with a tool when the source is a document (a spec, a standard, a rulebook) rather than retyped by hand — cite the extraction command and the page/section in the PR — and always run the mutation that must turn the test red · BECAUSE on project A a table-driven test compared each result with the function it was testing, so a wrong rule was green by construction; and separately, a fix and its test oracle hand-transcribed from the same document by the same author carried one identical misreading into both, while a sibling task that extracted the text with a tool and verified each changed entry against it caught the same class of error
- 2026-09-15 · confirmed · WHEN a rule asks an agent for a number or a key about its own run, or a repair is shipped for anything already broken (a rule, a fact, a structured document with a fixed schema) · DO ask only for what it can read from inside itself — wall-clock minutes, the basename of its working directory — in a fixed line and a single unit, with an explicit "not available" instead of a silent substitute; and before declaring the repair done, re-run a check over **the whole artefact**, not only the field or line that was touched, because a correction can carry the very defect it is correcting · BECAUSE a rule asking for turns, which no agent can count from inside, produced within hours three reports reading "290 s / 3 commits", "554s (~9,2 min) · 4 commits" and "~31 turns"; and the replacement written that same morning kept an agent id in the same line — just as unreadable from inside, and needed by nobody, since the usage report takes the real id from the launching session's transcript — so the next two agents filled it with their branch slug and with another agent's id, each fabricated key reading exactly like evidence; and on project A a restore of a session-handoff section header put it back above twelve facts instead of moving them first, declared fixed without running the one-line structural check that would have shown facts still sitting inside the log section — caught only two days later, by the next retro's own count
- 2026-09-15 · confirmed · WHEN a finding or a task hands the implementer a list of accepted forms, of call sites or of line numbers · DO regenerate the list from its producer with a command, quote the command, have the test rebuild it at run time — and when the only producer is the code's own announcement, anchor the list to the effect the class leaves behind instead · BECAUSE on project C a reviewer hand-copied six real forms out of a file holding seven and the parser was anchored to the six; and a task's Notes enumerated four call sites beside an AC reading "every path, present and future" — the enumeration is what got fixed, and the fifth path cost a whole extra round
- 2026-09-15 · provisional · WHEN a long check needs to be bounded or waited on · DO run it in the foreground with a bound that exists on every host (the runner's own, or `perl -e 'alarm N; exec @ARGV'`), never in the background and never wrapped in `timeout`/`gtimeout` · BECAUSE those two binaries are absent on macOS so the wrapped command never runs at all, and a suite left in the background idled a review for 31 minutes on a machine where the whole suite takes 31 minutes
- 2026-09-15 · provisional · WHEN a line is about to be written into shared memory (handoff facts, a session document, a report the next agent reads as state) · DO write only what a command just showed, with the command in the line, and mark anything else as an unverified assumption · BECAUSE on project A three lines describing an environment — a production deployment, migrations waiting to be applied, a hosting provider — were written from inference, none of the three existed, and a separate PR was needed to withdraw them
- 2026-09-15 · provisional · WHEN an agent writes to the project's shared memory while standing in a worktree · DO check who merges that branch first, and in a throwaway worktree write the line into the report instead of the file · BECAUSE on project A a reviewer's log line was committed onto a review scratch branch that nothing ever merges, and it survived only because its author noticed and said so
- 2026-09-16 · provisional · WHEN a class of cases is only visible through what the program announces (a printed line, a log entry, a counter it bumps) · DO write the criterion as the effect on the world and measure it outside the program's own output — the objects still standing after the run, compared with before, never line-count against summary — and put "produces nothing" in the case table as its own row · BECAUSE on project C an AC phrased as "the summary equals the number of kept lines" produced a faithfully derived test that stays green on a path keeping a branch in silence (0 == 0), and that fifth path survived both the fix and a grep of every announcement in the file
- 2026-09-17 · provisional · WHEN a report offers an exhaustive classification as its completeness evidence (every call site, every exit point, every occurrence, sorted into the buckets an invariant defines) · DO mark each row with how it was established — ran it, or read it — and actually run the rows where the invariant's own nouns change kind (a remote ref where the rule says "branch", a directory where it says "file"), because an unrun row is a hypothesis sitting in a table of facts and the exhaustive shape is what stops anyone doubting it · BECAUSE on project C a classification of all 43 exit points in one script, written to prove a fix complete after a round already lost to examples-instead-of-the-class, filed three sites under "already routes through keep()" that route through nothing; the reviewer established 3 of the 43 rows independently and 1 was false — the row where "branch" had quietly become a remote ref
