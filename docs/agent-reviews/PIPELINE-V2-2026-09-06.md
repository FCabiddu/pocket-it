# Pipeline v2 — 2026-09-06

Follow-up to the 2026-09-05 audit (kept privately: it contains client names and spend). The audit fixed what was broken; v2 changes how the pipeline is shaped, on the user's "carta bianca". Everything below is on branch `feat/pipeline-v2`.

## What changed and why

| Change | Why (evidence from the audit) | Where |
|---|---|---|
| **Fast lane `/quickfix`** | Most real work is small (on one real project: 26 EPIC-level items against 16 chores, welcome tweaks and a11y fixes); running BAD/TAD/IPD for a copy fix is pure waste | `.claude/skills/quickfix/` |
| **`/intake` in the main session** | Subagents cannot ask (7/7 `AskUserQuestion` failures); the right questions asked once are worth more than any assumption | `.claude/skills/intake/`, BA reads `BRIEF.md` |
| **Project TAD + delta per feature** | one project had 8 TADs and 9 IPDs repeating the same stack; developers read 600-line TADs for one endpoint | tech-architect Step 3, planner, developer, shared §3 |
| **One human gate: the board** | four documented review points were all skipped by the autonomous flow; the board is what gets built | `~/.claude/CLAUDE.md` |
| **Contract-first tasks** | frontend waited for backend in every story; a contract task (types/schema/OpenAPI) lets both run in the same wave | planner Step 3 + task template (`Contract`) |
| **`/run-wave` + `next-wave.sh` + `doctor.sh`** | orchestration was prose executed by the model, paying every turn; a script decides what is ready, the session only launches | `bin/`, `.claude/skills/run-wave/` |
| **`verify.sh` before review** | 40% of PRs needed rework, most for mechanical reasons; the reviewer now gets a ≤ 40-line lint/type/test summary and reads only green PRs | `bin/verify.sh`, reviewer Step 3 |
| **Given/When/Then → tests 1:1** | acceptance criteria were prose; now each AC is numbered, becomes one test, and the PR body maps them; the reviewer checks the mapping | BA template, planner template, developer PR body, reviewer |
| **`Risk` → model** | Sonnet everywhere, even for migrations/auth where an error costs a week; `Risk: high` runs on Opus | planner template, `next-wave.sh`, run-wave |
| **Resume, never relaunch** | 101 usage-limit kills and 241 interruptions restarted agents from zero; `maxTurns` output is resumable | `~/.claude/CLAUDE.md`, run-wave |
| **`retro` agent** | the same reviewer findings returned epic after epic; nothing fed back into best-practices | `.claude/agents/retro.md` |
| **devops-engineer removed** | 7 launches in two months vs 250 for developer; CI is opt-in; the rulebook lives in developer's DevOps section | developer.md `Label: DevOps` |
| **`usage-report.py`** | the cost spike was discovered from the bill; now it is a weekly command | `bin/usage-report.py` |

## An orchestrator in front (same day, second pass)

The pipeline is now orchestrator-agnostic: a private entry skill can sit in front of it and needs only two scripts and one file.

| Piece | What | Where |
|---|---|---|
| `bin/status.sh` | The project state computed from disk, ~25 lines: config, documents, board counts and open high-risk tasks, ready wave, open PRs with labels, worktrees, handoff facts and last log lines. Replaces `--resume` | `bin/status.sh` |
| `bin/handoff.sh` | The narrative memory, `docs/SESSION_HANDOFF.md`, now **mandatory** and written only through the script: `log` (dated line, kept to 40) at every PR and review by developer, reviewer, qa, run-wave, quickfix; `fact` (cap 30) only for gotchas and decisions | `bin/handoff.sh`, shared rules §6 |
| Entry skills | `/intake`, `/quickfix`, `/run-wave` are the only places that talk to the user; an external orchestrator routes to them | `.claude/skills/` |

Design choice, stated: the orchestrator is a main-session skill plus a rule, not an agent, because a subagent cannot talk to the user, does not receive background notifications, and would rebuild the 450k-context session the audit found. Its memory is on disk; the session stays thin.

Verified: `status.sh` on a real checkout (334 tasks, 34 ready, 4 open PRs, 6 worktrees); `handoff.sh` creates the file, prepends, keeps 40 log lines, adds facts idempotently.

## Verified

- `doctor.sh` on a real project board (185 committed task files, 9 DEPS.json): 0 errors, 15 warnings (old tasks without `Files`/`TAD`, two TADs missing §9.3, 21 legacy `/tmp` preference files).
- `next-wave.sh` on the same board: 1 ready, 1 in progress, 4 blocked with reasons, 119/185 done.
- `verify.sh` on a real PR: lint, type-check and affected tests green in 12 s, using the main checkout's `node_modules`.
- `usage-report.py --days 8` on a real project reproduces the audit numbers and flags the two sessions that implemented by themselves.

## Not done, deliberately

- No `Workflow`-tool script for run-wave: it needs an explicit opt-in per session; the skill recipe around two scripts gives most of the benefit without it.
- `documentation-agent` kept, marked optional, not folded into a task.
- The `ux-ui-designer` and `mvp-builder` bodies are untouched.
- Existing target projects keep their per-feature TADs; the next `tech-architect` run on them writes a delta against the newest one and recommends consolidation.
