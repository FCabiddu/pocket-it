# PI-7 — next-wave.sh va in TypeError con id di task alfanumerici — report

## Cosa è cambiato e perché
`bin/next-wave.sh` ordinava i task id con `sorted(status, key=lambda s: [int(x) if x.isdigit() else x
for x in re.split(r"[.\-]", s)])`. Confrontando due liste con tipi diversi nella stessa posizione
(es. `28` int da `T-28.5.5` contro `"BUG"` str da un id alfabetico) Python solleva
`TypeError: '<' not supported between instances of 'int' and 'str'` e lo script non stampa nulla:
la board diventa cieca a ogni wave finché quei task esistono.

Fix: `sort_key()` trasforma ogni segmento in una tupla omogenea `(0, int(x), "")` per i segmenti
numerici e `(1, 0, x)` per quelli alfabetici — i numerici restano ordinati fra loro, gli alfabetici fra
loro, e i due gruppi non vengono mai confrontati per tipo diverso, solo per la tupla `(0|1, ...)`.
L'ordine fra id puramente numerici resta identico a prima (stesso confronto `int < int`).

**Deviazione, in scope (stesso file):** scrivendo il test per l'AC3 (tre id, due dei quali con lo
stesso prefisso alfabetico e un suffisso numerico diverso: `T-BUG-1` / `T-BUG-10`) ho verificato che
la regex di cattura dell'id dall'header (`^#\s*([A-Za-z]+-[\w.]+)`, riga 19) tronca qualunque id con un
secondo trattino incorporato: `# T-BUG-1: …` diventava tid `T-BUG` (perde `-1`), e `T-BUG-1`/`T-BUG-10`
collidevano sullo stesso tid, sovrascrivendosi a vicenda nella board in memoria — un difetto distinto
ma imparentato (stessa causa di fondo: id "alfanumerici" non pienamente supportati), non citato nella
diagnosi del task ma necessario per far reggere l'AC3 come scritto. L'ho corretto nella stessa riga,
stesso file autorizzato: `^#\s*([A-Za-z]+(?:-[\w.]+)+)` cattura ogni segmento `-parola` ripetuto e si
ferma comunque prima di uno spazio (quindi `PI-7 — titolo`, con em-dash circondato da spazi, resta
`PI-7` come oggi). Nessun altro script in `bin/` usa questa regex o lo schema `isdigit()` (vedi sotto).

Ho anche aggiunto `bin/next-wave.test.sh` a `testCommand` in `.pocket-it.json`, seguendo la
convenzione già usata per `worktree.test.sh` e `doctor.test.sh` (vedi commit 00d18ee, 8ba36e8):
un nuovo `*.test.sh` va sempre agganciato al gate, altrimenti resta peso morto.
