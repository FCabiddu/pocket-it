# PI-35 — Uno script dice quando serve un retro

## What changed and why
`bin/retro-due.sh` (new): reads the handoff log and counts signals since the last `retro-mark` line —
(a) a `needs work` line whose `cause:` is present and is not `first-round`; (b) the same cause recurring
on two different tasks (first-round excluded, same as (a)); (c) a task reaching three or more `needs work`
lines (signalled once, at the third); (d) any `BUDGET`/`STALL` line. Exit 0 = `retro-due: nothing`;
exit 10 = `RETRO DUE: <n> segnali` + one `<task> — <tipo> — <riga di log>` line per signal; exit 2 = not a
git repository (input error).

`run-wave/SKILL.md` and `quickfix/SKILL.md`: a "Retro trigger" paragraph after every review call (first
round and delta re-review alike) — run `retro-due.sh`, exit 10 launches the `retro` agent right now, in
background, with the signal lines as scope, never asking, never waiting for the epic to close.

`.claude/agents/retro.md`: a "Retro-mark — the last thing you do" paragraph — once the project PR(s) are
merged, writes `retro-mark <date> <scope>` via `handoff.sh log`, through a small branch+PR+self-merge, the
same shape already used for the facts/best-practices PR and the lessons PR (never a direct push to base).

## Composer (AC4) — used, not just the fallback
The task said: use `bin/handoff.sh`'s read-only composer (`recent`/`grep`) only if it is already on `main`,
else the direct-file fallback, and note where to hook it later. **PI-14 (#63, "compositore in sola lettura
per la memoria della pipeline") merged into `main` while this task was in flight** — confirmed via
`git fetch origin && git log origin/main` before opening the PR. So `retro-due.sh` detects the composer by
grepping `bin/handoff.sh`'s own case grammar (`facts|show|recent|grep`) and, when present, reads
`handoff.sh recent --all` (newest-first, reversed to chronological); otherwise it reads
`docs/SESSION_HANDOFF.md`'s `## Log` section plus `docs/SESSION_HANDOFF_ARCHIVE.md` directly. Both paths
share the exact same signal logic — only where the chronological line list comes from differs. The fallback
stays live and is exercised by the whole test suite (bare git-repo fixtures with no `docs/handoff/`
fragments), so both code paths are proven, not just documented.

## Tests ↔ acceptance criteria
`bin/retro-due.test.sh`, 34 checks, all green:
- AC1: no file → `retro-due: nothing` / exit 0; one signal → exact `RETRO DUE: 1 segnali` + line / exit 10;
  not a git repo → exit 2 with a message.
- AC2(a): positive (cause present, ≠ first-round) and two negatives (cause: first-round; no cause field) —
  isolated on separate tasks so they cannot also trip (b)/(c).
- AC2(b): positive (same cause, two different tasks — only the second task's line is flagged `same-cause`)
  and negative (same cause, repeated rounds of ONE task — no `same-cause`, only two `needs-work-cause`).
- AC2(c): positive (third `needs work` line for one task, signalled once, causes kept at `first-round` to
  isolate the type) and negative (two lines is not enough).
- AC2(d): positive (`BUDGET`/`STALL` lines) and negative (lowercase "budget"/"stall" in ordinary prose does
  not match — case- and word-boundary-sensitive, not a substring).
- AC3: a `retro-mark` line hides every earlier line, tested mid-log and across the archive boundary (the
  hidden line lives in `docs/SESSION_HANDOFF_ARCHIVE.md`, the mark and the surviving signal in the main
  log); a matching log with no mark at all counts everything.
- AC4: `git status --porcelain` identical before/after from a project root with **no `docs/` directory at
  all** (the AC's own must-have case), and again with a populated log.
- AC5/AC6: `grep` assertions against `run-wave/SKILL.md`, `quickfix/SKILL.md`, `retro.md`.

**Mutation testing** (not part of the suite, run once to prove the tests are not vacuous, then reverted):
dropping the `cause != "first-round"` guard turned 6 checks red (AC2a/c/d negatives); dropping the
cross-task guard on `same-cause` turned 2 AC2b-negative checks red; dropping the retro-mark boundary
(`since_mark = chronological` unconditionally) turned all 4 AC3 checks red. `diff` against the pre-mutation
file confirmed a clean revert each time.

with the composer path active.
