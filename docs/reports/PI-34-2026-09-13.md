# PI-34 — verify.sh e il reviewer creano le worktree usa e getta sotto .claude/worktrees, mai in /tmp

## What changed and why
`bin/verify.sh` (line 16) hardcoded `WT="/tmp/pocket-it-verify/..."` for its throwaway scoped-test
worktree; `reviewer.md` prescribed `/tmp/{repo}-{branch}` twice (conflict resolution at line 39, local
verification at line 73). Both violate the project convention (worktrees under `<repo>/.claude/worktrees/`)
and are unusable from a sandboxed agent session with no write permission for `/tmp` — six reviewers in one
day skipped `verify.sh` for this reason and re-did checks by hand; some pushes from `/tmp` were also denied
by session permissions.

Fixed all three by moving to `<repo>/.claude/worktrees/`:
- `verify.sh`: `WT="$ROOT/.claude/worktrees/verify-$$-${BRANCH//\//-}"` — the `$$` (PID) prefix keeps the
  path distinct from any agent worktree's own slug (`worktree.sh` uses the bare slug with no prefix), so a
  reviewer verifying a branch never collides with, or touches, the agent's real worktree for it, even if
  the branch name naively slugs to the same string. Trap is armed (`WT=""`, a no-op cleanup) *before* the
  worktree is created, then covers `EXIT INT TERM` (was `EXIT` only) so a kill or Ctrl-C mid-run still
  removes it. Cleanup `cd`s back to `$ROOT` first (removing the worktree you're sitting inside is fragile),
  tries `git worktree remove --force`, and only on that failing falls back to `rm -rf` + `git worktree
  prune` (prune is scoped to `$ROOT` and only ever touches entries whose directory is already gone, so it
  cannot affect another reviewer's live worktree in the same repo). Also adds `.claude/worktrees/` to
  `.git/info/exclude` once, matching `worktree.sh`'s own convention.
- `reviewer.md` line 39 (merge-conflict resolution): now uses `bin/worktree.sh "$PWD" {branch}` (a real,
  locked worktree since this is genuine work — a merge commit gets pushed from it), then unlocked and
  removed with `git worktree remove --force` once the conflict is resolved and pushed.
- `reviewer.md` line 73 (local verification, scoped test run): now a throwaway
  `.claude/worktrees/verify-$$-{slug}`, always removed with `--force`, mirroring `verify.sh`'s own scheme.

## Giro 2 — review round 2, six findings, all measured

**1. Bloccante — verify.sh: SIGTERM/SIGINT exited 0 and printed GREEN, checks ran in the main checkout.**
Root cause: `trap cleanup EXIT INT TERM` runs `cleanup()` on a signal, but bash does **not** terminate the
script afterwards unless the trap itself calls `exit` — for a non-EXIT signal with a custom trap, bash
resumes the script exactly where the signal landed. Since `cleanup()` already `cd`s back to `$ROOT`, whatever
ran next (lint, type-check, the test command) ran there, against the main checkout, and the script still
reached its own final `echo "verify: GREEN"; exit 0`. Fixed: `trap cleanup EXIT` (unchanged) plus
`on_signal(){ trap - EXIT INT TERM; cleanup; exit "$1"; }` bound to INT (130) and TERM (143) — the explicit
`exit` inside the handler is what actually stops the script. Also added `guard()`, called before every check
(`lint`, `type-check`, the test command, and once more before the final GREEN/RED line), verifying `pwd -P`
is still the throwaway worktree; aborts with exit 2 otherwise.
Tests (`bin/verify.test.sh`, `kill_mid_run()` helper): SIGTERM and SIGINT each mid the test-run phase (a
per-branch `.pocket-it.json` `testCommand: sleep 2` gives the window), plus SIGTERM right after worktree
creation (a git shim that sleeps 1.5s after a real `worktree add`, for a second phase). Each checks: no
worktree left, the exact signal exit code (never 0), no `"verify: GREEN"` in the output, and the main
checkout's `git status --porcelain` and tracked-file mtime unchanged. Mutation-proved: reverting the trap to
`trap cleanup EXIT INT TERM` (no explicit exit) turns the exit-code assertions red for all three phases.
Gotcha hit while writing the SIGINT test: POSIX/bash makes an **async** command (`cmd &`) from a
non-interactive, job-control-off shell start with SIGINT pre-ignored — a `trap … INT` inside it then has no
effect (this is what the test harness itself does to be able to signal verify.sh mid-run; a real, foreground
invocation is unaffected). Fixed by adding `set -m` near the top of `verify.test.sh`; confirmed with a
minimal repro outside the test file before touching it. Logged as a fact in `docs/SESSION_HANDOFF.md`.

**2. reviewer.md:39 — conflict resolution reused, then removed, the developer's own worktree, losing WIP.**
`bin/worktree.sh "$PWD" {branch}` **reuses** the branch's existing registered worktree if one exists — the
one bug report literally named: the developer's own, mid-work, locked, with uncommitted changes. My round-1
fix called `worktree.sh --unlock … && git worktree remove --force "$WT"` on exactly that worktree once the
conflict was resolved. Fixed: conflict resolution now uses its own, separate, detached throwaway —
`WT="$PWD/.claude/worktrees/reviewer-conflict-$$-{branch//\//-}"; git worktree add -q --detach "$WT"
origin/{branch}`, merges, commits, `git push origin HEAD:{branch}` (no branch checkout needed to push), then
removes only that worktree. The prose states explicitly: never touch, unlock or remove any worktree already
registered for `{branch}` itself. Test (grep-based, `reviewer.md` is prose, not executable): asserts
`reviewer-conflict-` is present and the old `bin/worktree.sh "$PWD" {branch}` call is gone, and that the
"never touch…" sentence is present.

**3. reviewer.md:73 — `$WT` used `$$`, recomputed across two separate Bash calls names two different paths.**
Each Bash tool call is a fresh shell process; a `$$`-based `$WT` computed again for the removal step (a
different tool call) would target a path that was never created, leaving the real one orphaned. Fixed: the
prose now says explicitly to compute `$WT` once and chain creation, use and removal in a single command
(`git worktree add … && { … }; git worktree remove --force "$WT"`). Test: grep for the explicit
"created and removed in the same shell call" sentence.

**4. cleanup-merged.sh:138 — verify-*/wave-overlay-* orphans after a `kill -9` are kept forever.**
The existing `is_scratch()` only recognised `/tmp/*`, age-gated at 24h; a `.claude/worktrees/verify-*` or
`wave-overlay-*` orphan (unlocked, detached — the new families this PR and the reviewer's own wave-overlay
pass create) fell through to "kept (detached)" indefinitely. Fixed: split into `is_scratch_legacy()`
(`/tmp/*`, unchanged 24h-gated behaviour) and `is_scratch_new()` (`verify-*`, `wave-overlay-*`,
`reviewer-conflict-*` by basename) with a new `in_use()` check (`lsof +D <path>`, reading the actual listing
rather than lsof's own exit status — **measured lsof's exit code is 1 even when it printed a matching
process**, once the open file/cwd sits below the queried directory rather than at it exactly; this is now a
fact in the handoff). A `is_scratch_new` path is removed the moment no process has it open or as cwd, no age
wait; falls back to the legacy 24h rule only if `lsof` itself is unavailable. Tests (`cleanup-merged.test.sh`,
isolated fixtures added after the existing count-based assertions so none of those needed updating): an
unused `verify-*` worktree removed on the very next run (no 24h wait); a `wave-overlay-*` worktree with a
real backgrounded `tail -f /dev/null` process cwd'd into it kept, "in use"; removed on the run after that
process is killed. Mutation-proved: `is_scratch_new(){ return 1; }` turns all three assertions red.

**5. verify.sh — `.git/info/exclude` errored when launched from a linked worktree.**
`$ROOT/.git` is a **file** (a gitlink), not a directory, for a linked worktree; `mkdir -p
"$ROOT/.git/info"` failed there. Fixed: resolve the shared common dir via `git rev-parse --path-format=
absolute --git-common-dir` (modern git), falling back to `cd "$(git rev-parse --git-common-dir)" && pwd` for
older git, and write the exclude entry there. Test: runs `verify.sh` from inside a second, linked worktree of
the fixture repo; asserts no "not a directory" error, the run still completes, and the exclude line lands in
the **main** checkout's `.git/info/exclude` (shared, not per-worktree). Mutation-proved: reverting to
`$ROOT/.git/info/exclude` turns the no-error assertion red.

**6. verify.test.sh — the cleanup comment/logic still referenced the old shared `/tmp/pocket-it-verify`.**
Superseded by finding 1's original fix: verify.sh's worktree now lives under the fixture repo (`$M`, itself
under `$S`), so the test's own `rm -rf "$S"` already covers it. Removed the now-dead
`"/tmp/pocket-it-verify/${UNIQ}-"*` glob and updated the comment to say so.
