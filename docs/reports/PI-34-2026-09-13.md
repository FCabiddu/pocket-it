# PI-34 — verify.sh e il reviewer creano le worktree usa e getta sotto .claude/worktrees, mai in /tmp

## What changed and why
`bin/verify.sh` (line 16) hardcoded `WT="/tmp/pocket-it-verify/..."` for its throwaway scoped-test
worktree; `reviewer.md` prescribed `/tmp/{repo}-{branch}` twice (conflict resolution at line 39, local
verification at line 73). Both violate the project convention (worktrees under `<repo>/.claude/worktrees/`)
and are unusable from a sandboxed agent session with no write permission for `/tmp` — six reviewers in one
day skipped `verify.sh` for this reason and re-did checks by hand; some pushes from `/tmp` were also denied
by session permissions.

Fixed all three by moving to `<repo>/.claude/worktrees/`:
- `verify.sh`: `WT="$ROOT/.claude/worktrees/verify-$$-${BRANCH//\//-}"` — the `$$` (PID) prefix keeps the
  path distinct from any agent worktree's own slug (`worktree.sh` uses the bare slug with no prefix), so a
  reviewer verifying a branch never collides with, or touches, the agent's real worktree for it, even if
  the branch name naively slugs to the same string. Trap is armed (`WT=""`, a no-op cleanup) *before* the
  worktree is created, then covers `EXIT INT TERM` (was `EXIT` only) so a kill or Ctrl-C mid-run still
  removes it. Cleanup `cd`s back to `$ROOT` first (removing the worktree you're sitting inside is fragile),
  tries `git worktree remove --force`, and only on that failing falls back to `rm -rf` + `git worktree
  prune` (prune is scoped to `$ROOT` and only ever touches entries whose directory is already gone, so it
  cannot affect another reviewer's live worktree in the same repo). Also adds `.claude/worktrees/` to
  `.git/info/exclude` once, matching `worktree.sh`'s own convention.
- `reviewer.md` line 39 (merge-conflict resolution): now uses `bin/worktree.sh "$PWD" {branch}` (a real,
  locked worktree since this is genuine work — a merge commit gets pushed from it), then unlocked and
  removed with `git worktree remove --force` once the conflict is resolved and pushed.
- `reviewer.md` line 73 (local verification, scoped test run): now a throwaway
  `.claude/worktrees/verify-$$-{slug}`, always removed with `--force`, mirroring `verify.sh`'s own scheme.

## Tests ↔ criteria
All 9 new assertions in `bin/verify.test.sh` (plus the 6 pre-existing ones, unchanged):
- AC1 → `PI-34 AC1 — the throwaway worktree is created under <repo>/.claude/worktrees/`,
  `PI-34 AC1 — no worktree is created under the old shared /tmp/pocket-it-verify path`. Uses a `git` shim
  (logs real call args, then execs real git) to read the exact `git worktree add` target path — avoids a
  racy diff of the real `/tmp` (the fixture repo itself lives under a `mktemp` dir).
- AC2 → `PI-34 AC2 — a SIGTERM mid-run leaves no worktree registered`,
  `PI-34 AC2 — no leftover verify-* directory under .claude/worktrees`. A per-branch `.pocket-it.json` with
  `testCommand: sleep 2` gives a reliable 2 s window after the worktree is created (polled for) before
  `SIGTERM` is sent to the backgrounded `verify.sh` process; assertions poll (bounded) afterward.
- AC3 → `PI-34 AC3 — verify.sh completes despite an agent worktree at the same naive slug`,
  `PI-34 AC3 — the agent worktree's own uncommitted file is untouched`,
  `PI-34 AC3 — the agent worktree stays registered and locked, never removed by verify.sh`. Constructs a
  real locked worktree (`git worktree add` + `worktree lock`, an uncommitted marker file) for branch
  `agent-branch-with-slashes`, then runs `verify.sh` against a *different*, real branch
  `agent/branch/with/slashes` — its naive slug (`/` → `-`) is identical to the agent branch's own name.
- AC4 → `PI-34 AC4 — reviewer.md never creates a worktree at a literal /tmp path`,
  `PI-34 AC4 — every remaining /tmp mention in reviewer.md points to .claude/worktrees or worktree.sh`. Grep
  on the two lines' wording.
- AC5: full `verify.test.sh` run, 15/15 pass.

Mutation-proved locally (not part of the diff): reverting `WT=` to the literal `/tmp/pocket-it-verify/...`
path turns both AC1 assertions red; removing the `trap` line entirely turns both AC2 assertions red (note:
narrowing `trap cleanup EXIT INT TERM` back to `trap cleanup EXIT` alone did **not** turn AC2 red on this
bash/platform — bash already runs the `EXIT` trap on an uncaught `SIGTERM` here; keeping `INT TERM` explicit
regardless, per the task's note and as documented best practice, since that behaviour is not guaranteed
across bash versions/platforms); dropping the `$$` prefix (reverting to the bare slug) turns both AC3
functional assertions red (verify.sh no longer completes cleanly and the agent's WIP file is gone).
