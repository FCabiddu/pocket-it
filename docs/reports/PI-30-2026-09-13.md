# PI-30 — installed copy separate from the development checkout

**Status**: Done (draft PR) · **Branch**: task/pi-30-separate-live-install · **Risk**: high · **Budget**: 200, used ~40 turns (one interruption from the account spend limit, resumed on the same worktree)

## What changed and why
- `bin/install-live.sh` (new): creates or updates the installed copy (default `~/.claude/pocket-it-live`) only through `git clone`/`git fetch` of the published base branch. First install clones into a temporary sibling, validates it, then renames it into place. Updates are fast-forward only. It refuses (exit 1, copy untouched) on local changes to tracked or untracked files, on commits of its own, a wrong branch, a detached HEAD, a rewritten published branch, a destination that is a development checkout (it has linked worktrees) or a linked worktree, and a remote that is a local checkout with a working tree. Before any file moves it checks the target commit: guard.sh, agents, skills and install-live.sh must exist, and every `*.sh` in `.claude/hooks` and `bin` must parse. It prints the when-to-run line on help and on every successful run. The script body sits inside `main` so that a self-update cannot corrupt the running script.
- `bin/install-live.test.sh` (new): 36 cases against a scratch bare origin, a publisher clone and a dirty development clone.
- `README.md`: Setup rewritten around two folders. New subsections: "Keeping the installed copy current", and "Switching an existing setup" with steps 0–6, 1b and Rollback.
- `.pocket-it.json` (outside **Files**): the new test is added to `testCommand`, as a handoff fact requires. Without it the test would never run again.

## Notes / residual risk
- During a fast-forward, git rewrites files in place. A hook that fires in those milliseconds can find guard.sh missing and fail open. An atomic swap (release directories plus a symlink) would close that window; it was not done, because it would change AC3's "fast-forward" model.
- Once `~/.claude/agents` becomes a real folder of links, an entry added later to the folder it used to point to has to be linked by hand (the README says so). A personal script that rebuilds `~/.claude/skills` from the development checkout would undo step 4 (the README says so).
- Personal settings were not touched. The switch is left to the orchestrator.
