## Round 2 — review findings and fixes
1. **Fail-open hook when guard.sh is missing or half-written.**
   - The script no longer rewrites the copy in place. It clones beside the copy (`<dest>.next.<pid>`), checks the clone, then exchanges the two directories in one atomic swap: `renamex_np RENAME_SWAP` on macOS, `renameat2 RENAME_EXCHANGE` on Linux. If no atomic swap is available, it refuses.
   - Before the swap, the new guard.sh must **answer** correctly: exit 2 on a forbidden command, exit 0 on a harmless one. A guard that lets everything through, or blocks everything (lock-out), is refused, and `--rebuild` does not skip this check.
   - New `--rebuild` replaces a drifted copy through the same swap and keeps the drifted copy aside. It replaces the two `mv` commands in the README.
   - The README hook command is now `bash …/guard.sh || exit 2`. Step 3 appends `|| exit 2` and step 6 checks it, including that a missing guard file blocks. Rollback no longer depends on the installed copy existing.
   - New README section "If every Bash command is blocked": the way out without Bash is to edit settings.json by hand or with the Edit tool (the guard only covers the Bash matcher), set the command to `"true"`, open a new session, run `--rebuild`, then restore the command.
2. **Step 5 linked `.git`.** It is now excluded.
3. **Names of the checkout that steps 3 and 6 did not see.**
   - Step 3 expands `$HOME`, `${HOME}` and `~`, and FLAGs paths inside `bash -c`.
   - New step 5b, `find-names.sh`, searches settings, the scripts that hook commands run (also inside `-c` strings), every entry of `~/.claude/agents` and `~/.claude/skills`, and the optional `EXTRA` folders.
   - The loaders-vs-work-area rule is written in the README.
   - Step 6 ends with "ALL CHECKS OK — and N line(s) still name the checkout" instead of ALL OK while any name remains.
   - Found while testing: BSD `grep -R` does not follow a symlink given as an argument, so paths are resolved before searching.
