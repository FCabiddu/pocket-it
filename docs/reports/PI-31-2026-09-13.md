# PI-31 — agent worktrees locked while in use — 2026-09-13

**Status**: Done, round 2 pushed (draft PR #59) · **Branch**: task/pi-31-worktree-lock · **Turns**: ~25 round 1 + ~20 round 2, of 120 · BUDGET/STALL: no

## What changed and why
The cleanup script's only guard was its own "merged or not" judgement. Now a second, independent guard exists:
- `bin/worktree.sh` creates the worktree locked in the same git command (`worktree add --lock --reason`, git >= 2.36; older git: lock right after add), reason `pocket-it: agent worktree for <branch> since <UTC date>`. Reuse of an unlocked worktree locks it again; a locked one is left as it is. `--unlock <repo> <branch>` releases only a pocket-it lock (exit 0 released/not locked, 1 foreign lock, 2 no worktree).
- `bin/cleanup-merged.sh` reads the lock reason from the porcelain listing. A pocket-it-locked worktree is never judged by reflog or ancestry: clean and a merged PR whose head contains the tip → unlock and remove (relock if removal fails); otherwise kept with `locked: <reason>; <why>` (no merged PR contains its tip / commits not in merged PR #n / dirty / protected branch / git status failed). A foreign lock is never released. A pocket-it-locked worktree missing on disk: lock released, entry pruned, branch deleted only on the merged-PR condition. `merged_pr` extracted from `decide` (same behaviour for unlocked worktrees).
- `CLAUDE.md` script table row (outside Files): it said cleanup keeps every locked worktree.

## Lock lifecycle (launch request: released in every path)
- Script errors (missing base, branch checked out elsewhere): git fails before registering anything → no worktree, no lock (tested).
- Interruption of worktree.sh: the lock is part of the single `worktree add` call, so no half state; older git has a window where the worktree exists unlocked, never a lock without a worktree.
- Agent done / blocked / killed: an agent process cannot release on kill, and between review rounds the worktree is still in use, so the lock ends with the PR: cleanup-merged (run after every merge) releases and removes it. Abandoned work or a merge without a PR: `worktree.sh --unlock`. Locks do not accumulate silently: every kept locked worktree is listed with its date.
