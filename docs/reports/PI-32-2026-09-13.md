2. **Parole cercate nel testo libero.** Corretta la classe, non i due esempi:
   - Un piccolo lexer bash (virgolette singole/doppie, backslash, `$(…)` annidato nelle doppie, backtick, corpi di heredoc) sostituisce con `TEXT` il **valore** delle opzioni testuali: `-m`/`--message`/`-am` di `git commit|tag|merge|stash|notes`; `-b`/`--body`, `-t`/`--title`, `-n`/`--notes`, `--subject` (anche `--opt=valore`) di `gh pr|issue|release`; il corpo di un heredoc con delimitatore quotato letto da `git … -F -` o `gh … --body-file -`/`-F -`; la forma `"$(cat <<'EOF' … EOF)"` come valore.
   - Solo dati, mai codice: nessuna sostituzione se il valore contiene `$(…)`, backtick o process substitution, se il delimitatore dell'heredoc non è quotato, se il comando contiene `$'…'` o `case`, o se il lexer non chiude una virgoletta, una sostituzione o un heredoc. Nel dubbio il comando si legge intero (falso positivo, mai push mancato). Un errore del passo restituisce il comando grezzo.
   - Tutte le regole a parole leggono quel testo: divieto di merge agente (NORM), push agente lettura B, merge della sessione principale, pkill/killall, APP_STATUS, sleep, grep legacy del force-push (CMD). La lettura A resta sul comando grezzo.
   - Divieto di merge agente: in più ancorato come proposto dal reviewer (tra `gh`, `pr`, `merge` solo opzioni col loro valore), per i valori che non si possono sostituire.
   - Regola APP_STATUS: ora legge il testo senza virgolette e dentro il proprio segmento. Prima `gh variable set APP_STATUS --body "prod"` passava (STR) e `… --body dev && echo prod` era bloccato: entrambi erano la stessa classe di errore sulle parole.
   - Trovato durante il lavoro, stessa classe: la regex che toglie le stringhe fra doppie virgolette (CMD) voleva due backslash davanti a un carattere escapato, quindi un solo `\$` o `\"` rendeva visibile l'intera stringa a tutte le regole su CMD (una riga di diario con `\$5` e «pkill» veniva bloccata). Corretta: un backslash escapa un carattere.
