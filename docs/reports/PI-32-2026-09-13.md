# PI-32 — the guard tells the main session from an agent — report 2026-09-13

**Status**: Done, PR #54 draft (https://github.com/FCabiddu/pocket-it/pull/54), branch `task/pi-32-guard-knows-caller`, built on PI-13 as merged.

## What changed and why
- `guard.sh` reads the caller from the hook input. Claude Code adds `agent_id`/`agent_type` inside a subagent and leaves both out in the main session; the command and the repo files have no say in them. If either key is present, with any value, the caller is an agent (AC5).
- **Main session**: no behaviour change. The existing gate, classifier and prefixes are untouched, and all 179 existing rows are still green (AC2).
- **Agent, merge**: `gh pr merge` is denied even with the prefix. The check reads the quote-blind text, so `gh "pr" merge` and the REST `pulls/N/merge` form are caught too. The only exception is `agent_type` = `retro`, which still needs its prefix (AC3).
- **Agent, push**: the prefix is inert. The verdict is the stricter of two readings (AC1, AC7):
  - **Reading A** is the PI-13 quote-aware classifier.
  - **Reading B** deletes quotes and backslashes instead of pairing them, then checks each push segment. It denies a push when:
    - the command names main/master, or uses `--all`/`--mirror`/`--prune`, `:`, a glob, or a variable;
    - it is implicit and comes from a checkout on main, from an unresolvable `cd`/`-C`, or from a branch whose `@{push}` is main;
    - the command also carries push-changing config (`alias.`, `push.default`, `remote.*.push`, `GIT_DIR`, `--git-dir`, `send-pack` …), fails to parse, or uses ANSI-C hex/octal escapes.
- Pushes to task branches stay allowed (AC4). The block message says the base branch is forbidden to agents with or without the prefix, and where diary lines go: the agent's own task branch, or left uncommitted for the orchestrator (AC1).
- The header comment "WHO IS CALLING" covers the mechanism, the field check, why a prefix is not a permission, and the residue (AC6).
