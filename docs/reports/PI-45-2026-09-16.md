# PI-45 — doctor.test.sh non sa mutare uno script già mutato

## What changed and why
`bin/doctor.test.sh` had six self-mutating blocks that each build a patched copy of `bin/doctor.sh`
by reading the **live** `$SCRIPT` and doing a verbatim text substitution, then asserted (via
`assert`/`n == 1`) that the substitution applied — with no `set -e` and no check of that assertion's
outcome from the shell side. When the substitution failed (source text already mutated, e.g. by a
reviewer proving the suite isn't vacuous), the destination temp file was left empty/partial and the
shell ran a no-op mutant against unrelated fixtures anyway, producing spurious FAILs on checks that
never call the mutated function (repro'd: 16 FAILs, 9 artifacts, matching the task's own measurement).

Fix, applied uniformly to all six blocks (`mutate_has_section`, the `--accept-base` round-2 sed
block, the accept-base-on-deleted-base python block, the `_classify_base` sed range-replace, the
PI-37 marker-delete block, the PI-42 `re.subn` block):
1. Capture one pristine snapshot of `$SCRIPT` once, at setup, into `$SCRIPT_SRC` (AC3) — every block
   mutates that snapshot, never the live `$SCRIPT`, so two mutations in one run or an external one
   cannot interfere with each other.
2. Every python-side `assert`/uncaught exception that used to signal "substitution didn't apply" was
   converted to an explicit `sys.exit(1)`, checked by the shell with `if <build-mutant>; then ... else
   ok "…: cannot self-mutate: source text not found" 'false'; fi` (sed-based blocks use an
   equivalent `grep -qF <marker>` pre-check). On failure this reports exactly one named, isolated
   FAIL and **skips** the downstream assertions that would otherwise run against a corrupted mutant
   (AC1, AC2).
3. The real assertions inside each block are otherwise untouched — a genuine regression in the
   mutated function still makes them fail, against the right check (AC5).

## AC4 — search for other occurrences
`grep -n 'sed.*"\$SCRIPT"\|python3.*"\$SCRIPT"' bin/doctor.test.sh` before the fix found exactly six
call sites reading the live `$SCRIPT`; all six are the blocks fixed above. The same grep after the
fix returns exactly one hit: the new recursive regression test's own mutation step, which
intentionally mutates the real, live `bin/doctor.sh` (transiently, trap-restored) because its whole
purpose is to *simulate* the externally-mutated-before-the-suite-runs scenario — it is the producer
of that condition, not a consumer of a stale snapshot, so it is correctly exempt from AC3.

Siblings checked by grepping for the same pattern (`sed`/`python3 ... "\$SCRIPT"` building a mutant
copy) in every other `*.test.sh` and `.claude/hooks/*.test.sh` in the repo:
`bin/handoff.test.sh`, `bin/worktree.test.sh`, `bin/status.test.sh`, `bin/next-wave.test.sh`,
`bin/retro-due.test.sh`, `bin/verify.test.sh`, `bin/install-live.test.sh`,
`bin/install-live.readme.test.sh`, `.claude/hooks/guard.test.sh`, `.claude/hooks/guard.heredoc.test.sh`
— no matches in any of them.

`bin/cleanup-merged.test.sh` **does** have two call sites with the same shape (~line 322, PI-31 AC5;
~line 503, PI-38 AC5), each building a mutant from the live `$SCRIPT` via `sed`. Both already include
an explicit "mutant really differs from the script" verification right after building it, which is a
partial mitigation of the same class of risk — but that file is explicitly out of scope for this task
("owned by a concurrent agent: do not touch it and do not run its suite"). Reported here rather than
fixed; logged as a fact for a future task (see below), not silently left unrecorded.

## Acceptance criteria → tests
- AC1/AC2/AC3/AC5 → new recursive test at the end of `bin/doctor.test.sh`: backs up the real
  `bin/doctor.sh`, inserts a behaviour-preserving comment into `_has_section`'s definition line
  (an "external mutation"), recurses via `DOCTOR_TEST_NO_RECURSE=1 bash "$SELF"` against the mutated
  file, restores the original via `trap`, and asserts: (a) the named self-mutation error
  ("cannot self-mutate: source text not found") fires; (b) it is the **only** FAIL line in the
  recursed run; (c) three direct, non-mutation-sanity checks that don't touch `_has_section`
  (repo18's malformed-range, repo19's unrecognised-qualifier, repo16's AC5 out-of-order) still pass
  under the externally mutated script — isolation without blanket silence.

  scope-completeness check, not a behaviour).
- Existing 13 `ok` assertions inside `mutate_has_section`'s accept-anything/reject-everything section
  are unchanged and still gated behind the mutation succeeding — they cover AC5 for that function.
