# PI-62 — doctor fails when tasks/INDEX.md no longer matches the task files

## What changed and why
`tasks/INDEX.md` was generated by `bin/tasks-index.sh` but nothing verified the step actually ran
after a merge, so a stale row (e.g. a task the file marks `Done` still reading `Todo`, with no PR
link) reached `bin/status.sh` unnoticed — the orchestrator would then open on a board state that
disagreed with the disk it claims to trust.

Two changes, one home for the invariant:
- `bin/tasks-index.sh` gains a `--stdout` mode: it prints the generated table to stdout and never
  touches `tasks/INDEX.md`. The table-building logic itself (the `gen()` function) is untouched —
  only the sink changed (redirect vs stdout) — so there is exactly one implementation of the table,
  never two that could drift apart. Every existing caller (no `--stdout` flag) keeps writing the
  file and printing its `tasks-index: wrote …` line, unchanged.
- `bin/doctor.sh` gains a new check (`# 2d`, right after the PI-37 block, board section) that calls
  `tasks-index.sh --stdout`, compares the result against the committed `tasks/INDEX.md`, and
  **errors** (not warns) when they disagree, naming the task IDs of the differing rows and the exact
  one-liner fix command. Row comparison is cell-based (split on `|`, cells trimmed) so that a
  markdown-reformatting commit hook changing only pipe spacing can never manufacture a false
  positive; if the two texts differ but no row's cells actually differ, the message says so
  ("formatting-only difference") instead of blaming a row — verified manually (see Checks).

The check skips in silence, same house style as the rest of section 2: no `tasks/` directory at all
(AC5), or no committed `tasks/INDEX.md` yet at all (a board that has never run `tasks-index.sh` is a
different gap from staleness — there is nothing to compare against, and every one of this suite's
own pre-existing fixtures, repo1–repo19, has no INDEX.md and must stay green).

## Resume round (NEEDS WORK on PR #107)

**Finding 1 — closed — 3b13045.** `bin/doctor.sh`'s committed blob (not the working tree) carried a
byte-identical duplicate of `def _classify_base(base, env):` (lines 73-88), confirmed absent from
`origin/main`. Root cause: a race between an earlier `git commit` on this file and a concurrently
running background `nohup bash bin/doctor.test.sh`, whose PI-45 self-mutation fixture
(`classify_anchors_doubled`) mutates the real `bin/doctor.sh` in place before restoring it via trap
— the commit captured a mid-mutation snapshot even though the file was correctly restored on disk
moments later. This was the cause of the reviewer's 3 PI-45 recursion FAILs
(`classify_close_anchor`, `classify_anchors_doubled`, `AC1 has_section_literal`), whose
`src_anchors` checks expect the source text to appear exactly once. Fixed by removing the second
definition — confirmed a pure no-op (`bash -n` clean, `grep -c` → 1 occurrence, `git diff` shows
only the duplicate block removed). Lesson: never run a self-mutating test suite in the background
while committing the file it mutates.

**Finding 2 — closed — ce418bd.** `tasks/INDEX.md` was stale on this branch — `bash bin/doctor.sh`
correctly reported `ERROR tasks/INDEX.md is stale — differs from tasks-index.sh for: PI-62`, exit 1
— proof the check works, not a defect. Fixed by running the real generator (`bash
bin/tasks-index.sh`) and committing the regenerated file; no exception added for PI-62's own row.
`bash bin/doctor.sh` now reports `0 error(s)` on this repo's real board (63 task files).

Verification after both fixes: `DOCTOR_TEST_NO_RECURSE=1 bash bin/doctor.test.sh` → 197 ok / 0 FAIL;
