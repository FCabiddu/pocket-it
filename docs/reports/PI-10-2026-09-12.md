# PI-10 — third round: F3 (digit cluster) and F4 (deletion of the base branch)

## What changed and why
Delta re-review found the family of AC4 (force-push to main stays blocked even with the
authorization prefix) had two more members, both reachable only through the prefix
(BLOCKED without it, ALLOWED with it before this fix):

- **F3** — `is_force()`'s cluster regex was `-[a-zA-Z]+`, so a short-flag cluster mixing `f`
  with a digit flag (`-4`/`-6`, IPv4/IPv6) was not recognised as force. Fix: widen the
  character class to `-[a-zA-Z0-9]+`.
- **F4** — deleting the base branch is not a force-push, so the existing parser classified
  it as a plain `EXPLICIT` push and the prefix authorized it. This is worse than rewriting
  history: it removes the branch outright. Added a `destructive` verdict, independent of
  `is_force()`, that is set when: a `-d`/`--delete` flag (or a short cluster containing `d`)
  targets main/master; the refspec's source side is empty (`:main`, `:refs/heads/main`);
  or `--mirror`/`--prune` is present (these can remove main from the remote without ever
  naming it, so they are treated as always in scope). `destructive` feeds the same `force`
  variable the force checks use, so it is blocked unconditionally — `AUTHORIZED_PUSH` is
  never consulted for it, exactly like a force-push.

## Tests <-> findings
- F3: 4 new BLOCK cases (`-f4`/`-4f` × explicit main/master, `-4f` bare from a main
  checkout).
- F4: 8 new BLOCK cases covering `--delete`/`-d` (long form, short form, `refs/heads/`
  form, both branch names), empty-source refspec (`:main`, `:refs/heads/main`),
  `--mirror`, and `--prune` with a glob refspec — plus 2 BLOCK cases proving the same two
  forms (`--delete origin main`, `origin :main`) were already blocked *without* the prefix,
  so the fix does not depend on it.
- Controls (must stay ALLOW, not over-tightened): deleting a *task* branch in every one of
  the same shapes — `-d origin task/x` with and without the prefix, `--delete origin
  feat/old`, `origin :task/x`, plus the pre-existing `+task/x:task/y` control.
- Mutation-proved by hand: reverting the F3 regex, neutering `has_delete_flag`, dropping the
  empty-source check, and neutering `has_mirror_or_prune` each turned exactly their own rows
  red and nothing else — confirmed by running `guard.test.sh` against each mutated copy and
  restoring the clean file after.

## Deviations
None from the review's requested shape. `--mirror`/`--prune` are blocked unconditionally
(regardless of current branch or the specific refspec pattern) rather than only when a
literal `main`/`master` token appears, because both can remove main from the remote without
naming it (glob refspec, or no refspec at all) and the hook cannot know the full local ref
state to rule that out safely.
