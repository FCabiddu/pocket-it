# PI-10 — report

## What changed and why
`guard.sh` blocked every `git push` to `main`/`master` unconditionally, but the orchestrator's own
skills prescribe exactly that (board/index/memory updates on the base branch after a wave, or a
task file written before a worktree exists). Added `POCKET_IT_ORCHESTRATOR_PUSH=1`, the same
audit-prefix shape already used for `gh pr merge`: an audit trail, not a technical permission,
that authorizes a plain push (explicit or implicit) to main/master but never a force-push, which
stays blocked for everyone unconditionally.

## Implementation
- `AUTHORIZED_PUSH` flag set from the prefix regex (same shape as `POCKET_IT_USER_MERGE=1`).
- The two static "explicit main" regex blocks are now skipped when authorized.
- The Python branch-resolution block (implicit push, `-C`, `cd` chains) now also detects a force
  flag (`-f`, `--force*`) per push segment and reports `EXPLICIT_FORCE`/`IMPLICIT_FORCE`; those
  verdicts always block, regardless of `AUTHORIZED_PUSH`. Non-force `EXPLICIT`/`IMPLICIT` verdicts
  only block when not authorized.
- The segment regex now also strips a leading `POCKET_IT_ORCHESTRATOR_PUSH=1 ` before matching
  `^git`, so force/implicit-main detection still runs when the segment carries the prefix (without
  this, `PREFIX=1 git push --force` fell outside the `^git` anchor and slipped through — caught by
  a self-authored mutation test, see below).
- The pre-existing standalone force-push regex (line ~139, unconditional, text-only) is untouched:
  it remains a second line of defence for explicit forms.
- Updated `.claude/skills/quickfix/SKILL.md` (two spots: the task-file push in §2, the close-step
  push in §4) and `.claude/skills/run-wave/SKILL.md` (§5 close-the-wave push) to use the prefix.
- **Deviation** (files outside the task's `**Files**:` list): `.claude/skills/intake/SKILL.md` had
  the identical bare `git push -q` on what is the base branch at intake time — the exact bug this
  task describes. Fixed it too and said so here, since leaving it would reproduce "a task file
  never reaches origin" for the very first skill in the pipeline. `deps/SKILL.md` was checked and
  needed no change: its only "push" line is a cross-reference to quickfix's already-fixed one.
