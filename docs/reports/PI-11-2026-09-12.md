# PI-11 — verify.sh recognises shell tests

## What changed and why
`bin/verify.sh` line 51 detected "test files in the diff" with a regex covering only
JS/TS/Python/Go naming conventions (`\.(test|spec)\.[cm]?[jt]sx?$|_test\.(py|go)$`). This
repo's own tests are all shell (`bin/*.test.sh`, `.claude/hooks/*.test.sh`), so the check
never matched and printed `warn no test files in the diff` on every PR, including PRs that
added test cases — making the warning permanently uninformative.

Fix: added a `\.test\.sh$` alternative to both the presence check (`grep -qE`) and the count
(`grep -cE`) on that line, keeping the two aligned per the task's note. Deliberately scoped to
`*.test.sh`, not `*.sh`, so a plain non-test shell script still trips the "no test files"
warning (AC2).

## Tests <-> acceptance criteria
No test previously existed for `verify.sh` — declared per the task's "Tests expected" section.
Added `bin/verify.test.sh` (6 assertions), driving the real script against a scratch git repo
with a bare `origin` remote and feature branches per case (no mocks):

- AC1 — branch adding `bin/newthing.test.sh` -> `info test files in diff: 1`, no false warn.
- AC2 — branch adding only `bin/plainscript.sh` (non-test) -> warning still fires, unchanged.
- AC3 — branch adding `src/foo.test.ts` + `pkg/bar_test.go` -> `info test files in diff: 2`,
  count unchanged from before the fix.
- Extra — mixed case, one shell test + one JS/TS test in the same diff -> counted together (2).

All 6 assertions pass (`bash bin/verify.test.sh` -> `verify.test.sh: ALL PASS`).

## CI fix — PR #35 review (2026-09-12)
Reviewer verdict: NEEDS WORK, one blocking finding, one non-blocking note. Both closed on the
same branch, no new PR (commits `8acf9a9`, `2da5de5`):

- **F1 (blocking)** — `bin/verify.test.sh` was not registered in `testCommand` in
  `.pocket-it.json`, the only one of the repo's eight test scripts missing from it. As
  delivered, the new self-test ran once (in review) and would never run again on a future
  diff — the exact failure mode the task itself was fixing. Fix: appended
  `&& bash bin/verify.test.sh` to `testCommand`. Verified by running the full chain: all 8
  suites exit 0, `verify.test.sh` included among them.
- **Non-blocking** — `cleanup()` in `verify.test.sh` did `rm -rf "$S" "/tmp/pocket-it-verify"`,
  deleting the whole shared directory `verify.sh` uses for its own throwaway worktrees. Two
  parallel runs (two agents running `verify.sh`, or two runs of this test) would delete each
  other's in-flight worktree. Fix: the test's scratch repo directory is now named after the
  `mktemp`-unique run id (`$UNIQ`) instead of the literal `main`; since `verify.sh` derives its
  worktree path from `basename($ROOT)-$BRANCH`, this makes every run's worktree path unique.
  `cleanup()` now removes only `/tmp/pocket-it-verify/${UNIQ}-*`, never the shared directory
  itself. Verified the directory is left empty after a run (no residue) and that the glob only
  ever matches this run's own prefix.
