## The invariant, and why the suggested fix is not it

The invariant is *no mutation may be declared applied on the strength of evidence that a truncation
also satisfies*. The review suggested mirroring the PI-37 block's dual boundary `grep -qF` on
`$SCRIPT_SRC` before the sed. That shape was **built and executed** against the review's own
reproduction, with no other change:

```
### The reviewer's suggested fix EXACTLY (dual boundary grep -qF, no whole-line match, no post-flight)
rc=1  FAILs=7
    FAIL  mutation (round-2 text-based classify), same fake git: degrades to a warn — proves the test is not vacuous
```

It does not close the finding. `grep -F` is a *substring* match: the line with the trailing comment
still contains the anchor text, so the pre-check passes and the range still runs away. The PI-37
site's own dual grep is nevertheless correct **for its own address**, which is `/…/` and not `/^…$/`
— which is exactly why the gate below takes the matching mode as an argument instead of assuming one.

## What was built

One gate at the top of `bin/doctor.test.sh`, with its threat model stated above it (what it protects
against; what is deliberately left to the assertions themselves and to doctor.sh's own checks), used
by all six self-mutation sites, copied nowhere:

- `src_anchors <file> <line|substr> <count> <anchor>…` — every anchor the address uses is counted in
  the captured source **before** sed runs, `line` (`grep -xF`, mirroring `/^…$/`) or `substr`
  (`grep -F`, mirroring `/…/`), and must occur exactly as many times as the address assumes. This is
  what covers the class rather than the one executed case: removed, edited in place, or doubled,
  opening anchor or closing.
- `sed_lit <literal>` — the address is *built* from the same strings that were counted, so the line
  the gate counts and the line sed matches cannot drift apart. (The `_classify_base` address was
  previously hand-escaped in a heredoc, one edit away from disagreeing with any check placed next to
  it.)
- `mutant_whole <file>` — anchor-independent post-flight: the patched copy still parses as bash, the
  python heredoc it opens is still closed by its own delimiter, and that python still compiles. This
  is the layer that holds for a future range whose author forgets to declare an anchor at all.
- `mutation_applied <mutant> <marker>` — the only way a block may conclude "applied": marker landed
  **and** `mutant_whole`. Every refusal sets `MUT_WHY`, quoted verbatim in that block's own named
  `cannot self-mutate: …` failure.

Both layers are necessary; neither is sufficient. Measured: a **doubled closing anchor** closes the
range early and produces a copy that is whole and carries the marker, over a span the block never
meant (the real closing line is left behind) — only the count sees it. A **runaway** produces a
fragment — `mutant_whole` sees it without knowing any anchor, `bash -n` alone does not.

The same gate was applied to the five sites the review had cleared, which is what makes it a rule
rather than a second copy: sites 2 and 5 now declare their anchors and build their addresses from
them; sites 1, 3 and 6 (python) now report their reason on stderr so the shell can name it, site 3
additionally requires each of its two `str.index` boundaries to occur exactly once (it silently took
the first before), and all six end in `mutant_whole`.

## AC4 — the rule, not the call site

The review established by `grep -n ',/\^' bin/doctor.test.sh` that site 4 was the only range-address
block and that there is no seventh site. That is a snapshot of a moment. Two things replace it:

- **One shared home.** There is no shared library across `bin/*.test.sh` in this repo (checked: no
  `source`/`.` of a common file in any of them), and creating one would mean editing files owned by
  concurrent agents. So the rule's home is the top of `bin/doctor.test.sh`, defined once and called
  from all six sites — no second copy to drift. The `bin/cleanup-merged.test.sh` follow-up task
  should move these three functions to a shared file and call them, rather than copy them.
- **The file now enforces its own coverage.** It counts its self-mutation sites from its own text
  (the `mktemp …/doctor-mut…` declarations) and its own gate calls, and asserts they are equal:
  `ok    AC4: … 7 sites declared by their own mktemp, 7 gate calls, no site ungated and no copy of
  the rule`. A seventh site added later without a gate turns this red the day it is added, instead
  of waiting for the next reviewer to mutate `bin/doctor.sh` and be told the wrong test broke.
  Proven both ways: adding an ungated `mktemp` site → `FAIL … 8 sites …, 7 gate calls`; removing one
  gate call → `FAIL … 7 sites …, 6 gate calls`.

The class was also re-established across the siblings rather than taken from the finding:
`grep -rn ',/' bin/*.test.sh .claude/hooks/*.test.sh | grep -i sed` → two hits, site 5 here and
`bin/status.test.sh:69` (a range over a *command's output*, not a script mutation). Per-file
occurrences of "mutat": `bin/cleanup-merged.test.sh` (2 real sites, out of scope, tracked),
`bin/doctor.test.sh`, and `bin/handoff.test.sh` / `bin/verify.test.sh` /
`bin/install-live.readme.test.sh` / `.claude/hooks/guard.test.sh`, whose hits are comments
("mutation-provable"), fixture edits or an env override — none of them builds a patched copy of the
script under test by text substitution, so none is in the class. Those four files were read only,
never edited, and their suites were not run.
