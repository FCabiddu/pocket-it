# PI-9 — 2026-09-12

## What changed and why
`bin/handoff.sh` resolves the repo to write to from `git rev-parse --show-toplevel`
(the current directory), and its `log`/`fact` confirmations said only "handoff: logged" /
"handoff: fact added" — no indication of *where*. An agent in a worktree that forgets a
`cd` writes into the wrong checkout silently; the mistake surfaces much later as an
unexplained change elsewhere. The script's repo resolution is correct and untouched per
the task's Notes — only the confirmation messages of `log` and `fact` were extended to
name the absolute path they wrote to.

Changed messages (all previously-successful paths, `p`/`$F` is the absolute
`$ROOT/docs/SESSION_HANDOFF.md`):
- `log`: `"handoff: logged"` -> `"handoff: logged — $F"`
- `fact` added: `"handoff: fact added"` -> `"handoff: fact added — {p}"`
- `fact` already present: `"handoff: fact already present"` -> `"handoff: fact already present — {p}"`
- `fact` cap-reached (still exit 0): appended `" — {p}"` to the existing stderr warning

The exit-3 refusal message at the cap (an unsuccessful call) is untouched, as required.

## Deviations
While writing the new PI-9 tests, exact substring matches against the script's own
`$ROOT`-derived path failed on this machine: `mktemp -d "$TMPDIR/…"` returns a path under
macOS's `/tmp` symlink, but `git rev-parse --show-toplevel` returns the resolved
`/private/tmp/…` (or `/private/var/folders/…`) path — same directory, different string.
Fixed by resolving the test's temp dir with `pwd -P` right after `mktemp`, in both the
pre-existing `$S` and the new `$S9`. This is a test-harness fix only; the script's own
resolution and the two pre-existing exact-match tests were otherwise correct.
