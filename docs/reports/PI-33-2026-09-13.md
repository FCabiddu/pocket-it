## Round 5 — NEEDS WORK, 1 finding (review `11bfe79`)
Cause: round 4 defined **disposable** strictly on the engine axis ("real-and-not-shared"). Every non-real database (in-memory, pg-mem, H2, any fake) fell into **shared** by complement, and the shared-write ban then forbade writing to a database a normal unit test uses every run. Coordinator's decision: the category to define strictly is the one the rule protects against — **shared** (harm), not disposable. Reviewer's round-5 text kept the wrong shape (real gating the shared/disposable split, non-real databases "neither"); rewritten from scratch per the coordinator's spec (commit `e99d322`):

- **shared** = existed before this run, OR another process/person/agent/run can read or write it while you use it (config-pointed database you did not create, an already-running server's own databases, persistent dev DB, staging, production).
- **disposable** = every other database, no exceptions — created this run and gone before it ends, including in-memory and stand-in engines (pg-mem, H2, any fake).
- **real** = a separate axis (genuine engine vs stand-in), decides only whether a `real DB` requirement is met, never whether a write is allowed.

Case → category, the reviewer's 9 cases plus round 4's 6, run against the new text only (row 141/143), each in exactly one category:

| Case | Category |
|---|---|
| Created and not removed | shared (fails "gone before it ends") |
| `createdb` + `dropdb` on an already-running server | disposable; every other database on that server stays shared |
| Existing staging instance | shared; restoring a dump over it is a write to a shared database |
| Container started this run, left running | shared (fails "gone before it ends") |
| Container started this run, stopped and removed before it ends | disposable |
| SQLite `:memory:` opened by a SQLite project's test runner | disposable (real, ends with the process) |
| pg-mem/H2 standing in for Postgres | disposable and not real — was never shared, so the shared-write ban never applied |
| SQLite (disk or memory) standing in for Postgres | disposable and not real, same reasoning |
| Test database a config file points at, created and removed by you | disposable — config never decides |
| Container started by another session | shared (not created by you in this run) |
| Persistent local development database | shared |
| Test database kept from earlier runs | shared |
| Persistent `app_test` database reused across runs | shared |

No case falls into neither or both category; no normal test pattern (an in-memory or stand-in-engine database used and discarded within the run) is banned by the shared-write rule.

Resume report format:
- closed — `e99d322`: shared redefined strictly (existed before, or accessible to another process/person/agent/run while in use); disposable is its exact complement, no exceptions — in-memory and stand-in engines included.

Verification: `bin/doctor.test.sh` green; the 13-row table above walked case by case against the committed text.
