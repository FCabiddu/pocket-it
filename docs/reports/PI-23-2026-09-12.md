# PI-23 — report

## What changed and why
`.claude/agents/shared/design-compass.md`, three edits, no scope beyond the file named in the task:

1. **Display line-height** (Typography principles): the `0.88`–`1.0` tightened range is kept — the character stays — but it now reads as a starting guess, not a floor. Added: the actual floor is the font's own `ascent + |descent|` (from `hhea`/`OS2` ÷ `unitsPerEm`), typically `1.05`–`1.15` for shallow-descender grotesque/condensed sans and `1.2`+ for serif/script display faces with deep descenders; how to find it for a given font (metrics tool or `fonttools ttx`, or render `gjpqy` at the candidate value inside the real wrapper and look for a cut descender at both breakpoints); and the fix below the floor (raise the line-height, or `padding-bottom` on the wrapper, never on the text).
2. **New invariant**, same section: "No clipped glyphs, ever" — no descender/ascender/diacritic cut at any width, checked on the rendered page, never deduced from the CSS. This is AC4's explicit rule.
3. **Technique #1 (split-text line reveal)**: noted the outer `overflow: hidden` mask is permanent (not just for the animation's duration) and sized by the same line-height — so a tightened line-height without compensating room clips descenders forever after the reveal ends, not just mid-motion. Fix: `padding-bottom` on the outer.
4. **Technique #2 (clip-path wipe reveal)**: the real mechanism, not just a warning — `inset(0 0% 0 0)` is not "no clip", it is a clip drawn at the element's own box edges and held there if the animation rests on its final frame. Before this technique touches an element, tight-line-height text simply overflows its line box unclipped (default `overflow: visible`); adding `clip-path` at all turns that same box into a hard clip boundary, permanently, once the animation stops on `inset(0 0% 0 0)`. Fix: size the box to the font's full glyph height first, or drop to `clip-path: none` once the reveal completes instead of resting on the "full" inset.
5. Added a cross-reference line in "Universal animation rules" pointing any future masking/clipping technique back to the no-clipped-glyphs invariant.

## Calculation shown (task requirement)
Worked from the causal figures already in the task (a font with rendered glyph height 1.2 em, ~0.25 em reserved for descenders, tightened to line-height 0.92) to verify the general rule before writing it:
- Leading = line-height − (ascent+descent) = 0.92 − 1.2 = **−0.28 em** (negative: the box is smaller than the glyph).
- Half-leading per side (CSS applies it symmetrically to the ascent and descent portions of the line box) = −0.28 / 2 = **−0.14 em**.
- Effective descent portion of the line box = 0.25 − 0.14 = **0.11 em** below baseline — matches the task's own "circa 0.1 em" figure.
- The glyph's actual descender ink still reaches the font's full 0.25 em below baseline, so **≈0.14 em (roughly half the descender) falls outside the line box** and is clipped by anything bound to that box.
- Minimum safe line-height for this font = ascent+descent = **1.2**, i.e. above the compass's entire `0.88`–`1.0` range — confirming the range needed the floor-finding method added, not just a lower number.
