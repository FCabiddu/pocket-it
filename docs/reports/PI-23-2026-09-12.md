# PI-23 — report

## Round 2 — supersedes round 1's formula

Round 1 wrote a general rule ("safe minimum line-height = ascent + descent") derived
from a single worked example without measuring it on other fonts. The reviewer
measured it in Chromium and found it wrong in both directions. This round replaces
that rule with what pixel measurement on two real fonts (Baskerville — serif, deep
descenders — and Avenir Next — sans, plus Helvetica and Rockwell as corroborating
sans/slab data points) actually shows, keeps the `0.88`–`1.0` display range live
(AC5), and fixes the two proposed remedies that were themselves unsafe.

## Method — pixel-only, in a real browser, two fonts minimum

All numbers below come from Playwright/Chromium (`chromium` launched headless,
macOS system fonts Baskerville, Avenir Next, Helvetica, Rockwell — all present on
this machine). Two scripts, run and their output pasted in full:

**Ink-vs-metrics probe** (`geom.mjs`): renders each case twice, once with
`overflow: hidden` and once with `overflow: visible`, screenshots a generous crop
around the element, and diffs the raw PNG bytes — a real pixel truth, not a DOM
measurement. It also reads `Range.getBoundingClientRect()` and `scrollHeight` on
the same elements to show where those disagree with the pixels.

```
Avenir Next  lh=1.12  pixels-clipped=false  rangeRect-overflows=true   scrollHeight>clientHeight=true
Helvetica    lh=1     pixels-clipped=true   rangeRect-overflows=true   scrollHeight>clientHeight=true
Rockwell     lh=1     pixels-clipped=true   rangeRect-overflows=false  scrollHeight>clientHeight=false
Baskerville  lh=0.92  pixels-clipped=true   rangeRect-overflows=true   scrollHeight>clientHeight=true
translateY(110%) hidden before reveal with room .25em: false
translateY(calc(100% + .6em)) hidden: true
clip-path inset(0 0% 0 0) cuts glyphs: true
clip-path inset(-.4em) cuts glyphs: false
```

Reading it: Avenir Next (ascent+descent = 1.366 em) is pixel-clean at `1.12` even
though both DOM signals claim overflow (false positive from the DOM). Rockwell
(ascent+descent = 1.0 em) clips at `1.0` in pixels while **both** DOM signals say
nothing overflows (false negative from the DOM) — the DOM box is not the ink,
in either direction. Helvetica clips an accented capital (`ÈCCO HEADLINE`) at
`1.0`, but plain caps (`HEADLINE`, no diacritic) are clean at `0.90` (next script)
— so the safe minimum depends on which glyphs the actual headline contains, not
on the font alone.

**Remedy probe** (`clip.mjs`): sweeps the two proposed fixes for the masking
techniques (#1 outer `overflow:hidden`), measuring both whether pixels clip and
whether the line-to-line pitch (distance between two stacked instances) changed:

```
Baskerville  lh=0.92 padneg2 pitch=0.920em  clipped=no
Helvetica    lh=0.9  padneg2 pitch=0.900em  clipped=no
Baskerville  lh=0.92 padbot  pitch=0.920em  clipped=YES
Baskerville  lh=0.92 none    pitch=0.920em  clipped=YES
Baskerville  lh=1.15 none    pitch=1.150em  clipped=no
Avenir Next  lh=1.12 none    pitch=1.120em  clipped=no
Avenir Next  lh=1    none    pitch=1.000em  clipped=YES
Rockwell     lh=1    none    pitch=1.000em  clipped=YES
Helvetica    lh=0.9  none    pitch=0.900em  clipped=no
Helvetica    lh=1    none    pitch=1.000em  clipped=YES
Baskerville  lh=0.92 pad     pitch=1.120em  clipped=YES
Baskerville  lh=0.92 padneg  pitch=1.120em  clipped=no
```
(`padbot` = `padding-bottom:.25em;margin-bottom:-.25em`; `pad` =
`padding-bottom:.2em` alone; `padneg` = `padding:.2em 0;margin:-.2em 0` — split
top+bottom; `padneg2` = `padding:.25em 0;margin-bottom:-.5em` — padding both
sides, all the compensating negative margin on the bottom only.)

Reading it: round 1's remedy (`padding-bottom` alone, row `pad`) still clips
(the accented capital has no room added above it) **and** widens the pitch from
`0.92` to `1.12` — it fails on both counts the review named. Splitting the
negative margin top/bottom (`padneg`) stops the clip but still widens the pitch
to `1.12` (adjacent margins don't fully collapse when split). Only `padneg2` —
room on both sides, all the negative margin on one side, sized to the total
padding added — holds the original tight pitch (`0.92`/`0.90`) with nothing
clipped, on both a serif with a descender+accent and a sans headline.

## What changed in `.claude/agents/shared/design-compass.md`

1. **Display line-height** (Typography principles): removed the "ascent + descent"
   formula and the per-family ranges entirely — both measurably wrong (Avenir
   Next clean at `1.12` despite a `1.366` metric sum; Rockwell clips at `1.0`
   despite a `1.0` sum). Kept `0.88`–`1.0` as the live range (AC5). Replaced the
   formula with the measured fact that the safe minimum depends on which glyphs
   the actual headline text contains (plain caps vs. lowercase with descenders
   vs. accented caps), cited with the four data points above, and the only
   reliable method: render the real text at the candidate value and check pixels.
2. **No clipped glyphs, ever**: removed "DOM inspection of the actual glyph box"
   (the DOM box is not the ink, per the false positive/negative above) — the rule
   now says pixel comparison (clipped vs. `overflow:visible; clip-path:none` on
   every ancestor) or `canvas.measureText().actualBoundingBox{Ascent,Descent}`,
   never `getBoundingClientRect`/`scrollHeight`.
3. **Technique #1 (split-text line reveal)**: replaced `padding-bottom` with the
   measured-correct fix — `padding` on both sides, all the compensating negative
   margin on one side (not split), sized to the total padding added — plus the
   `translateY` note: `110%` leaks ink into the padded room before the reveal
   starts (measured `false`/hidden failed), `calc(100% + Xem)` with `X` at least
   the padding added keeps it hidden (measured `true` at `X=.6em` against
   `.25em` top padding).
4. **Technique #2 (clip-path wipe reveal)**: removed "size the box to the font's
   full glyph height" (repeats the wrong formula) — now says the risk is on all
   four sides (italic overhang left/right, not just vertical), cites the
   measured italic-serif case (`inset(0 0% 0 0)` clips, `inset(-.4em)` doesn't),
   and gives the same two exits: a verified negative inset or `clip-path: none`
   once the reveal ends.
5. **#8 (marquee)** and **#13 (polygon morph)**: added, per the review's finding
   5 — #8's `overflow: hidden` parent needs the same room as #1 for a tight
   line-height; #13's hover polygon insets every edge 3–5% for the whole hover,
   which can cut text near an edge. Cross-reference line in "Universal animation
   rules" now names #1/#2/#8/#13 explicitly and says "verified on pixels... not
   from the DOM box".

## Acceptance criteria → coverage (unchanged from round 1, remedy corrected)

- AC1 — line-height entry states the minimum depends on the composed glyphs, not
  a font-family bucket; measured examples given; method is pixel rendering. Done.
- AC2 — line-by-line technique: correct remedy (padding both sides + one-sided
  negative margin) that actually holds the pitch and doesn't clip; the reveal's
  starting offset fixed too. Done.
- AC3 — curtain technique: final state must not clip on any of 4 sides; measured
  negative-inset fix given. Done.
- AC4 — explicit no-glyph-clipping rule, verified on pixels, DOM inspection
  explicitly excluded as a method (it produces both false positives and false
  negatives, measured). Done.
- AC5 — `0.88`–`1.0` kept live, not walked back to "never safe"; the fix explains
  when the tight end is fine (plain caps, no diacritics) instead of banning it.
