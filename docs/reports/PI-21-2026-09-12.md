# PI-21 — report

## What changed and why
Four prose/config files (`run-wave`, `quickfix`, `reviewer.md`, `retro.md`) send mechanism decisions to the user instead of handling them. Fixed the three concrete defects named in the task plus a mid-task scope change from the owner on AC2.

- **AC1 (`run-wave`).** One reviewer per wave (`maxTurns: 60`) stalled on a 7-PR wave: 60/7 ≈ 8.6 turns/PR, not enough once one PR needs conflict resolution or a local scoped-test run. Now: groups of at most 4 PRs (60/4 = 15 turns/PR, ~2x headroom), `ceil(n/4)` reviewer Agent calls launched in parallel in the same message.
- **AC2 (`run-wave`, `quickfix`) — scope corrected mid-task.** Original draft prescribed escalation (opus/split/park) as the response to a red PR after two rounds — the owner flagged this as fixing the symptom, not the cause. Replaced with: before relaunching, classify **why** the previous round didn't close it, at minimum among three families evidenced by real PRs — (a) the finding/task named an example, not the whole class (a security guard finding closed for two command shapes, bypassed by a third) → fix by enumerating the class in the task/finding; (b) the base moved under the PR (a shared default changed on main; branch tests stayed green against the old state) → fix by merging/rebasing onto the current base and rerunning scoped tests before resending to review; (c) the verification itself reintroduced the defect (a report/check proving a name's absence typed that same name) → fix by describing the check by its effect, never by repeating the forbidden content. The fix goes where the cause lives, then the PR is resent with that correction. Parking remains only as a last resort after this analysis (or when the cause recurs), never as a response to a round count.
- **AC3 (`reviewer.md`, `retro.md`).** Both files now separate closing open points into `ORCHESTRATOR:` (mechanism — never a question for the user) and `HUMAN:` (genuinely human only) when they exist, and `retro.md`'s "Not actioned" bucket is restricted to real one-offs, not a parking spot for a fixable pipeline snag.
- **AC4/AC5.** Reread all four files whole; removed "the user decides" (blocked-list handling in `run-wave`), "reported to the user" (unresolvable dev blocker in `run-wave`), "say so and stop" over a dirty working tree (`quickfix` — the developer works in its own worktree, the dirty tree never reaches it), and the two-round → user handoffs (AC2). Every remaining human-only stop names the single point and says to continue the rest (blocked-task list, dev blocker, review escalation, close-wave report).
- `reviewer.md` also: delta-mode reviews now open with a one-line cause (even when the gap was the reviewer's own); a finding about a class of unsafe forms must enumerate the whole class, not one or two examples (this is literally why one project's PR needed a third round).
- `retro.md` also: Step 1 now collects the cause of each multi-round PR, not just the round count; Step 2's pattern table gained a "Review rounds" bucket grouped by cause.
