# PI-44 — cleanup-merged.sh: kept-count and invented cause

## What changed and why
`kept` was only incremented by `keep()`; five call sites (not the two the task's Notes named)
printed a `kept …` line without it: `drop_branch()`'s delete-failure, `reap_remote_branches()`'s
push-failure, and two more inside `locked_entry()` (protected branch; missing-on-disk with no
merged PR). All five now route through `keep()` — no new call site can skip the counter without
also skipping the announcement, since `keep()` is the only thing that prints "kept ". The test
derives the invariant generically (`kept_equals_summary()`: count of `^kept ` lines in stdout ==
the number the summary line reports) instead of enumerating call sites, so a sixth kept-path added
later is covered without editing the test.

For (b): `reap_remote_branches()` now tells apart, on a failed `git push --delete`, "the remote
ref does not exist" (branch already gone — reported, never counted as kept, never re-attempted)
from every other failure (genuine — counted as kept, reported via a new `remote_push_cause()` that
joins git's own stderr into one line, filtering only the noise "To <url>" line, falling back to
"cause unknown"). No cause is asserted that git did not itself state.

## Acceptance criteria → tests
- AC1: `kept_equals_summary` asserted after every real/dry-run/idempotent invocation across the
  suite (dry-run, main run, 2nd/3rd run, `--all`, PI-31 lock fixtures, PI-38 R8 fixtures) +
  dedicated mutation `PI-44 AC1 mutant: the invariant catches the regression` (reverts
  `drop_branch`'s `keep()` call to its exact pre-fix raw `echo`, proves the suite goes red).
- AC2: `PI-44 AC2 push-delete failing: … with the cause git itself gave` / `never the old guessed
  cause` (real `chmod -R a-w` on a bare origin → real "Permission denied" from git, not simulated).
- AC3: `PI-44 AC3 already-gone remote branch: reported, never claims a cause it never established` /
  `not reported or counted as kept` (git wrapper no-ops the script's own `fetch --prune -q origin`,
  branch deleted directly on the bare origin so R8's own tracking ref stays genuinely stale — a
  real race, not a stubbed message).
- AC4: `AC1+AC4 dry-run summary's kept count equals the kept lines actually printed`.
- AC5: same push-delete-failing case as AC2 — exit 0 unchanged, still reported as a failure, still
  counted (fix for (b) never turns a genuine failure silent).
- AC6: comment block above `reap_remote_branches()` rewritten to describe the already-gone/genuine
  distinction and the AC1 counting guarantee it now provides.

### Root cause and how completeness was established
Cause named by the reviewer: **example-not-class** — the task's Notes enumerated four call sites
(`drop_branch`, `reap_remote_branches`, two inside `locked_entry`) instead of stating the
invariant ("every path that leaves a branch or a worktree in place goes through `keep()`"), so a
fix that visited the four named sites was still incomplete at a fifth, unnamed one.

To show the list is now complete rather than that the two named variants were visited: I grepped
every `continue`/`return 0`/`return 1`/bare `return` in `bin/cleanup-merged.sh` (43 occurrences)
and classified each one:
- Helper predicates whose `return`/`continue` produce a reason string for a caller to decide with,
  not a decision themselves: `merged_into`, `merged_pr`, `decide`, `protected`,
  `is_scratch_legacy`, `is_verify_scratch`, `worktree_clean`, `flush`, `q`-style utility returns.
  None of these leaves a branch or worktree in place on their own; they report to a caller that
  does.
- Every remaining decision point — `drop_branch`'s own early returns, the loop inside
  `reap_remote_branches` (skip/continue lines for header rows, active branches, protected
  branches, "no match found"), `locked_entry()` (all six of its keep/return pairs), the "current
  worktree" and "locked" cases at the top of the main loop, the "detached", "no branch",
  "protected", "dirty", "git status failed" and `decide()`-fails cases at the bottom of the main
  loop — already routes through `keep()` (round 1 fixed the first two; the rest were already
  correct).
- The **only** decision point not already routing through `keep()` was the "prunable" case's two
  sub-paths, exactly the finding. This is the boundary: nothing else in the script exits leaving a
  branch or worktree in place without a `keep()` call.

### Fix
Both prunable sub-paths now mirror the ordinary loop's own
`why=$(decide "$sha" "$branch") || { keep "$p" "$why"; continue; }` pattern (the location the
reviewer suggested, used rather than beaten): `decide`'s stdout is captured, not discarded, and
the protected case gets its own `keep "branch $branch" "protected"` instead of a bare `continue`.
