## Round 7 — box-reference mismatch on bordered scrollers, opening sentence count

### Why
Round 6's scrollable-container fix was measured only on containers **without** a border. `overflow` clips a scrolling container at its **padding-box**; `clip-path: inset()` with no reference box defaults to the **border-box**. On a container with no border the two boxes coincide, so the mismatch was invisible; on a bordered container they sit `border-width` apart, so the reset's clip on the excused side lands further out than the shipped page's own clip ever did — reopening a strip the width of the border where scrolled-off content shows through, on the side that is supposed to be excused entirely. Separately, the Exclusions paragraph's opening sentence ("Four techniques… each excuses one side only") contradicted its own five-item list, where the marquee excuses both horizontal edges and `sr-only` excuses every side — a future agent reading only the opening sentence would apply "one side" to those two by mistake.

### What changed
- `.claude/agents/shared/design-compass.md` § **Glyph-clipping verification**, **Exclusions**:
  - Opening sentence: "Four techniques… one side only" → "Five techniques… each excuses only the side(s) performing the truncation — one side for ellipsis, line-clamp and scrollers, both horizontal edges for the marquee, every side for `sr-only`", matching the list below it.
  - **Scrollable containers** bullet: both `clip-path: inset(...)` values in the reset shot get `padding-box` appended (`inset(-1em -1em 0 -1em) padding-box` vertical, `inset(-1em 0 -1em -1em) padding-box` horizontal), plus a sentence naming the box-reference mismatch as the cause and the measured false positive it produces without the fix.
  - Checked every other `clip-path: inset()` in the same paragraph for the same class: `-webkit-line-clamp`'s mention of `clip-path: inset(-1em -1em 0 -1em)` (line 70) is not the applied technique — it is the rejected approach kept as a documented failure (a `clip-path` cannot know where a line boundary falls; the actual fix is the word-span wrap + `offsetTop` grouping described right after it) — no `padding-box` added there, since nothing there is ever compared against a bordered container's `overflow` clip. Ellipsis and marquee use `overflow-clip-margin`/`overflow-x`/`overflow-y`, no `clip-path`. `sr-only` excludes the element entirely, no `clip-path`.
