# PI-24 — round 3 (PR #48 delta review)

## Why this round
Round 2's delta review (f795086..e334819) found the verifications proved the wrong thing:
1. `getAnimations().map(a => a.finished)` hangs forever when any animation on the page is `infinite` (marquee, pulse), so the A.0 screenshot script never finishes on a real page.
2. The "font metrics (preferred)" check in `qa-engineer.md` compared `measureText` **sizes**, not **positions** — wrong on a wrapped multi-line title (whole-string width vs a single-line box) the same way the DOM-rect check round 1 removed was wrong.
3. The pixel-diff tolerance threshold (~200px, "order of magnitude above ~20px noise") passes real clips smaller than that, and the ellipsis/marquee/line-clamp exclusions dropped the whole element instead of just the truncated axis.

## What changed
- `.claude/agents/ux-ui-designer.md` A.0 item 1: run the screenshot script from a scratch folder outside the audited project (`npm i playwright` there once) — the audited folder has no `node_modules`, so `import { chromium } from 'playwright'` and `npx -p playwright` both fail there; report a clear one-line message instead of a stack trace if even that install is unavailable.
- Same file, A.0 item 2: removed the wait on `document.getAnimations().map(a => a.finished)`. Screenshot with `page.screenshot({ animations: 'disabled', caret: 'hide' })` instead — Playwright fast-forwards finite animations and resets infinite ones, so neither a fading-in hero nor a running marquee blocks the shot. `waitUntil: 'networkidle'` replaced with `'load'` (networkidle times out on polling pages, per round-2 review finding 3).
- `.claude/agents/qa-engineer.md` "Rendered layout": rewritten around **pixel-position comparison** as the only proof (where the ink falls against the clipping ancestor's padding box), in four numbered steps: settle without waiting on `getAnimations()`, shoot a fixed padded region, neutralise the *full* clip family (`overflow`, `clip-path`, `clip`, `contain: paint|content|strict`, `content-visibility`, `mask`, `-webkit-mask-*` — not just the two named in round 2), diff only the strip outside the ancestor's padding box with **no tolerance threshold**. `measureText` demoted to an optional per-line filter (baseline position per rendered line, never the whole string, never the primary check).
- Same section, exclusions: rewritten to be per-axis, not per-element — ellipsis/marquee excluded **horizontally only**, line-clamp excluded **below its last line only**, and the exclusion binds to the specific ancestor doing the intentional truncation, not every ancestor in the chain (an undersized wrapper around an ellipsis title still fails on its own vertical clip).
- `tasks/PI-24-nobody-looks-at-the-rendered-app.md` Notes: updated to match — measureText's whole-string form is now called out as wrong the same way the DOM rect is, pixel-position stated as the only valid proof.

## Mutations verified (scratch Playwright harness, not committed to the repo)
Built three throwaway fixtures and ran the round-2 wording against them, then the round-3 fix, in `/private/tmp/.../scratchpad/pw-verify` (outside the repo, discarded):

1. **Animation hang** — a page with a fading hero, a below-fold `IntersectionObserver` reveal, and an infinite marquee. Round-2 script (`getAnimations().finished`, bounded to 15s for the test): no screenshot, still hung. Round-3 script (`animations: 'disabled'`): screenshot in 668ms, hero at full opacity, below-fold heading revealed.
2. **measureText false red** — a title wrapping to 2 lines in a 420px box, no real clip. Whole-string `measureText` width: 530.5px vs a 420px box → false FAIL under the round-2 "preferred" method. Pixel-position diff (as-is vs `overflow: visible`, same region): 0 px → correctly PASS.
3. **Threshold false negative / axis exclusion** — a heading in a box 4px shorter than needed: whole-region diff 68px (round-2's ~200px threshold → PASS, false negative); pixels outside the ancestor's padding box: 15px (round-3, no threshold → correctly FAIL). A separate case: an ellipsis title inside an undersized wrapper clips 1871px outside the padding box on the vertical axis alone — a per-element "ellipsis excluded entirely" rule would have skipped it; the round-3 per-axis rule still catches it because the vertical clip belongs to the wrapper, not to the ellipsis mechanism.
