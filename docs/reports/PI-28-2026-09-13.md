**`.claude/skills/run-wave/SKILL.md`**
- New `### 4b. Overlay verification` step between review (Step 4) and merge (Step 5): once every group's review is back, builds one throwaway worktree with every APPROVED PR of the wave merged onto the base, in merge order, and runs the scoped tests there — before any `gh pr merge`. Skips entirely (no cost) when the wave has at most one APPROVED PR. Red → no merge yet; fix goes to the PR merged **second** in the pair that broke (never the one merged first, which was reviewed and tested alone); relaunch its developer with cause `other: overlay conflict with PR #{n}`, delta re-review, rebuild the tree. Green → merge normally.
- Step 4's developer-relaunch prompt now carries every finding still open **across all rounds**, not just the current one, and is barred from scope-narrowing language ("no other changes", "only fix the above"); the relaunch asks the developer to state which finding is closed and which is still open in its report.
- Step 5's "Session hygiene" bullet rewritten: compaction is automatic (`autoCompactWindow`), so the wave no longer waits for a user `/compact` keystroke before continuing; replaced with "never suspend work waiting for compaction".

**`.claude/agents/reviewer.md`**
- Declared the exception to "never the full suite" right where that rule lives (Step 3), naming who runs the overlay pass (`run-wave`, not the reviewer, not per-PR) and why (review groups of ≤3 never otherwise share a tree before the base).
- Two new finding-writing rules in Step 4: (1) any correction proposed in a finding is executed against the project's real data before it is written down; (2) a finding about a class of anything names the class's dimensions next to its examples, not just the examples.
