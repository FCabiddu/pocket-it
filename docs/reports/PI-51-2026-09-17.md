# PI-51 — Reinstall the shared checkout after a lockfile merge, and fail verify on a stale install

**Label**: DevOps · **Risk**: high · **Budget**: 200 · **Branch**: `task/pi-51-reinstall-shared-checkout`

## The invariant this implements

No verification may pass while the installed tree disagrees with the lockfile, and no reinstall may happen
while anything is running against the shared checkout. Both halves are stated as the harm, in the code and in
the skills: *a verdict about code that is not installed is not a verdict*, and *no reinstall while anything is
running against this checkout — it would swap the installed code under a run in progress and corrupt what
that run measured*.

## What changed

### `bin/install-drift.sh` (new) — the whole mechanism, one script, two questions

* `check [dir]` — compares the installed `node_modules` with the lockfile. Exit **0** match (or nothing to
  compare), **1** drift, **2** usage, **3** no verdict possible. It prints, per drifted entry,
  `drift  <name> — installed X, locked Y (<path>)`, and a summary that always states **how many entries it
  compared**, so a clean answer can never mean "nothing was read".
* `reinstall [dir]` — decides whether a reinstall is needed (effect first: the drift check; event second:
  `--since <ref>` over the lockfile names, used only where there is no drift check for that package manager),
  then whether it may run now, then runs the lockfile's own frozen install. Exit **0** done or nothing to do,
  **1** drift persisted / install failed / package manager absent, **3** cannot tell, **4** deferred.
* Flags: `--since <ref>`, `--except <branch|slug>` (repeatable — the merged PR's own worktree), `--running
  "<what>"` (the caller's knowledge that it launched agents; processes are out of the script's model on
  purpose, which is exactly why this flag exists), `--dry-run`, `--no-log`.

Threat model, written at the top of the script and honoured in every branch — **never a silent pass**:

| dimension | what the script does |
|---|---|
| scoped `@scope/name` | compared like any other; the path is split on the last `node_modules/`, so the scope stays part of the name |
| transitive-only / nested (`node_modules/a/node_modules/b`) | compared; npm v2/v3 `packages` paths and v1 recursive `dependencies` both |
| npm lockfile v1 / v2 / v3, `npm-shrinkwrap.json` | read; v2 is read once, from `packages` |
| a lockfile shape it does not understand | `NOT SUPPORTED — … declares neither "packages" nor "dependencies" (lockfileVersion N)`, exit 3 |
| a lockfile it cannot parse | `NOT SUPPORTED — … cannot be parsed`, exit 3 |
| pnpm / yarn / bun | `NOT SUPPORTED — drift check not supported for <pm> (<lock>)`, exit 3 — stated, never clean |
| two lockfiles in one tree | the readable one is compared **and** the other is declared uncompared in the same run |
| a package installed at an unreadable version | drift (`installed version unreadable`), not a pass |
| a package the lockfile requires and the tree lacks | drift (`locked Y, not installed`) |
| optional / platform-restricted absent, workspace `link`, an entirely absent dev set | not drift — and each is counted out loud (`N not comparable, M legitimately absent`, `all N dev entries … are absent`) |
| `node_modules` borrowed through a symlink | followed on purpose: that borrowed tree is the one being measured |

Deferral is conservative by construction: any worktree of the checkout under `.claude/worktrees/` or
`.worktrees/` defers, `--running` defers, and **a worktree list that could not be read defers too** ("an
unread list is never an empty one"). A false defer costs a printed line; a false proceed corrupts a running
measurement.

### `bin/verify.sh` — the guard

* After the borrowed-`node_modules` block and **before the first check runs**: `install-drift.sh check .`.
  Drift ⇒ `FAIL  install drift …` plus the drifted entries, where the borrowed tree came from
  (`node_modules is borrowed from <path>`), a fix that is runnable as printed (`install-drift.sh reinstall
  <the shared checkout>` — not the throwaway worktree, which is deleted seconds later), and
  `verify: could not run — the installed tree disagrees with the lockfile (nothing was measured)`, **exit 2**.
  Exit 2, not 1, keeps PI-41's meaning intact: a stale install is not the branch's defect, and nothing valid
  was measured. `NOT SUPPORTED` becomes a `warn` line and the run continues.
* Fail-closed on its own absence: a `verify.sh` without `install-drift.sh` next to it exits 2 rather than
  skipping the guard.
* The same rule on the base side of the PI-41 attribution: a base worktree whose borrowed install is not its
  own lockfile's cannot answer "does this check fail at the base too", so the attribution goes to **unknown**
  (with the reason and the reinstall command), never to "pre-existing on base".

### `.claude/skills/quickfix/SKILL.md` (Step 4) and `.claude/skills/run-wave/SKILL.md` (Step 5)

After the merge and the `git pull --ff-only`, both close by running `install-drift.sh reinstall .` on the
shared checkout, with `--running "{what you launched}"` whenever a developer, reviewer or QA agent is still
working against it; both state the harm rather than a place; both report the script's last line; both say that
exit 4 is a deferral already written to the handoff log with `handoff.sh log`, to be re-run once those agents
report, and that exit 3 is re-run with `--since {the base commit}`.

### Bookkeeping

`.pocket-it.json` `testCommand` now chains `bash bin/install-drift.test.sh` (a suite not in `testCommand`
runs once and never again). `CLAUDE.md`'s script table gained the `install-drift.sh` row and the extended
meaning of `verify.sh`'s exit 2.

Class-by-construction and anti-vacuity: the lockfile loops read the script's own `LOCKFILES` declaration at
run time (a new package manager is covered without touching the suite) and are held above a floor list that
belongs to the suite (a declaration that shrank cannot silently empty the loops); every `OK` assertion also
asserts the **number of entries compared**, so "clean because nothing was read" fails; a package manager the
declaration grows but the suite's command table does not know fails with "add it, do not skip it"; the
verify-level pairs are world mutations — one byte of an installed `package.json` — run in both directions.

## Defects the suite found in the implementation

1. **The deferral never fired.** `live_worktrees()` piped `git worktree list --porcelain` into `python3 - …
   <<'PY'`: the pipe and the heredoc both claim stdin, the pipe won, and python tried to execute the git
   output as its program. The reader silently produced nothing, i.e. "no worktree is running", which is
   precisely the wrong answer for this guard. Fixed by passing the porcelain in the environment
   (`WT_PORCELAIN`), and hardened: a reader that exits non-zero now defers instead of proceeding.
2. `--since` built its reason line with `printf '%s'` before `tr '\n' ' '`, so a single changed lockfile came
   out as `pnpm-lock.yamlchanged since …`.
3. `verify.sh` printed install-drift's own `run \`npm ci\` in <dir>` line, which named the throwaway worktree
   about to be deleted — a command that is not runnable as printed. It now prints the borrowed tree's origin
   and a fix aimed at the shared checkout.

## Notes, deviations and what is deliberately not covered

* `bin/install-drift.sh` and `bin/install-drift.test.sh` are new files; the task's `**Files**` line
  anticipated them. No other file outside that line was touched.
* Not covered, deliberately and stated in the code: the **contents** of an installed package (a package
  edited in place at the version it declares), and drift checking for pnpm/yarn/bun — those produce an
  explicit `NOT SUPPORTED` line and a `warn` in `verify.sh`, because refusing every pnpm/yarn/bun project
  outright would buy nothing anyone can act on. `reinstall` still works for all of them.
* Liveness is read from worktrees and from what the caller declares with `--running`; **processes are not
  inspected**. A bare `npm test` running in the main checkout with no worktree registered is not detected —
  that is what `--running` is for, and both skills instruct the caller to pass it.
* One assertion in `install-drift.test.sh` (the package manager missing from `PATH`) is skipped with a
  printed `note` on a host where `npm` shares a directory with `git` or `python3`; it ran here.
* No best-practices folder exists in this repo (`find . -type d -name best-practices` is empty), so the
  rulebook's fallback would have been a web search; the repo's own facts and conventions were used instead.
* `pipeline: false` — no CI workflow was created or touched.
