# PI-39 — handoff.sh log: normalizzare un messaggio che comincia già con la data

## What changed and why
`bin/handoff.sh log` always prepended `- $(date +%Y-%m-%d) ` to the message (line 274). A caller
passing a message that already started with an ISO date produced a doubled-date line — two real
examples shipped on `main` (from commit `f70db11`), and the second date shifted `NEEDS_WORK_RE`'s
"second token = ID" anchor onto a date, so R4F1 in `bin/retro-due.test.sh` went red and dragged
`verify.sh` red on unrelated PRs (this is what surfaced during PI-37's review).

Fix, in `bin/handoff.sh`'s `log` case only (no other file's logic touched):
- strip every leading `YYYY-MM-DD ` run (a caller can double it) before prepending today's date;
- if what remains is itself exactly an ISO date with nothing else (the limit case: the message IS
  just a date, no trailing space to strip against), drop it too — the line still ends up with one
  date, today's.
- Only a **leading** match (anchored `^`) is ever touched; a date elsewhere in the free text (AC2)
  is untouched by construction (the loop/check never look past the start of the string).

Data fix (AC3): the two doubled-date lines on `docs/SESSION_HANDOFF.md` were corrected in place —
only the redundant duplicate date token (plus its trailing space) removed, rest of each line kept
byte-for-byte identical (verified with `git diff`, 2 lines changed, minimal diff, no word touched
besides the removed date). `docs/SESSION_HANDOFF_ARCHIVE.md` had zero such lines (checked, both
files, before and after).
