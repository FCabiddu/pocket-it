## What changed and why
Two loose ends left open by PI-41, both "a check that can pass while proving nothing":

**(a) `bin/verify.sh`** — the "Not covered, deliberately" comment on `base_blockers` (top of the function,
:139) now names the branch/base worktrees' shared `node_modules` (symlinked from the main checkout at :112
and :279) as a third thing no exit code can settle: a branch check that writes into it changes what the
base re-run reads, so exit 3 ("inherited") can be reported for a reason that is not the base's own. This is

directs naming it instead; `reviewer.md`'s existing hand-re-run rule already covers the vector.

**(b) `bin/verify.test.sh`** — the `full`/`marked` sandbox package scripts (`lint`, `type-check`,
`typecheck`, `test:affected`) were hand-typed at line 528. They are now **derived** from the same

new `scripts_named()` helper reuses `base_blockers`' own `shlex`/pm/pmrun state machine and, critically, its
own `PMSUB` list of package-manager subcommands (read out of `verify.sh` with `grep`/`sed`, never retyped)
so the list stays in one home. `full`'s `package.json` is now built from the union of every producer's
derived script names; `marked`'s stays the explicit `{"scripts":{}}` it already was.

## One rule, one home (AC2 note)
Reused `base_blockers`' `pmsub` list rather than duplicating it: `PMSUB=$(grep -o 'local pmsub=" [^"]*"'
"$SCRIPT" | sed -E 's/^local pmsub="//; s/"\$//' | head -1)` extracts the exact string value out of
`verify.sh`'s source, byte-for-byte (including its leading/trailing space, which is how the `*" $tok "*`
substring match works both there and in the new `scripts_named()`). A subcommand added to that list in
`verify.sh` is excluded by `scripts_named()` too, with no edit to the test file.
