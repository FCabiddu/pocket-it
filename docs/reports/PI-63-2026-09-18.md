# PI-63 — Le fixture di auto-mutazione non devono scrivere sul sorgente in uso

## What changed and why
`bin/doctor.test.sh`'s PI-45 recursion (`SCRIPT`/`DOCTOR_BACKUP`/`restore_doctor`/`trap`, ~lines 1471-1547)
swapped the real, checked-out `bin/doctor.sh` in place to reproduce three external-edit cases, then restored
it via `restore_doctor` after each case and via a `trap … EXIT`. Neither protects a concurrent reader — a
`git commit`, a second test run, an editor autosave, another agent — from observing the mutated file during
the window; a duplicated `_classify_base` already landed inside a real commit this way.

Rebuilt the recursion so it never opens the real `$SCRIPT` for writing at all:
- `external_mutation` now reads from `$SCRIPT_SRC` (the once-captured copy every other self-mutating block
  in this file already uses) and writes the mutated text to a throwaway file under `$S`, never to `$SCRIPT`.
- `mirror_run` builds a throwaway directory per case: `bin/doctor.sh` is the mutated copy (a real file), and
  every other entry of the checkout — every top-level file/dir except `bin` and `.git`, and every other file
  under `bin/` — is a symlink to the real, current one. The recursed suite's own `pwd -P`/`cd ..`/
  `dirname "$SCRIPT"` path resolution then lands on real content for everything except the one file under
  test. First cut only symlinked `.claude/hooks` and `.claude/skills`; a full run surfaced 3 unrelated FAILs
  from repo17's F1 regression, which reads `../tasks/PI-14-…md` — fixed by symlinking the whole checkout
  minus `bin`/`.git` instead of hand-picking paths, so any future relative read is covered too.
- Removed `DOCTOR_BACKUP`/`restore_doctor`/the trap swap entirely — nothing needs restoring because nothing
  is touched.

## Acceptance criteria → tests
- AC1 (no window, proven not by construction) — a background reader (`SCRIPT_WATCH_PID`) `cmp -s`-samples
  `$SCRIPT` against `$SCRIPT_SRC` every 20ms for the whole run; a final `ok "AC1: bin/doctor.sh on disk
  never differed…"` checks it never saw a diff. **Mutation-tested**: reintroduced a `cp "$mut" "$SCRIPT"`
  inside `mirror_run` (a full mutated copy of the fix restoring exactly the old bug) — the AC1 check went
  red (`FAIL AC1: bin/doctor.sh on disk never differed…`), `bin/doctor.sh` was actually observed dirtied
  (`git diff --stat` showed 1 line changed) before I reverted both files.
- AC2 (fixtures still catch the same breakage, both directions) — the existing `AC2 ($rcase — $rwhat)`
  assertions in the RCASES loop (unchanged expectations, now fed through `external_mutation`+`mirror_run`)
  cover the forward direction (mutated → the named FAIL). Added `AC2 control (both directions)`: recursing
  on an *unmutated* copy of `bin/doctor.sh` must report none of the three `cannot self-mutate:` FAILs.
  **Mutation-tested** both ways: (a) reintroducing the `$SCRIPT` write (above) left the control green,
  because copying unmutated content back is not itself a corruption the "cannot self-mutate" checks see —
  expected; (b) feeding the control call a genuinely mutated file (`external_mutation "has_section_literal"`
  instead of a plain `cp` of `SCRIPT_SRC`) turned it red (`FAIL AC2 control…`), proving it is not vacuously
  green regardless of input.
- AC3 (no case lost) — `bin/doctor.test.sh` case count compared against `origin/main` (9a6dde5, a fresh
  `git worktree add --detach`): baseline 215 ok / 0 FAIL, elapsed ~141s. This branch: 218 ok / 0 FAIL,
  elapsed ~210-211s (215 baseline + 3 new: AC1 final check, AC2 control, AC4 SIGINT). No case missing.
- AC4 (SIGINT mid-recursion leaves the checkout clean) — spawns `external_mutation`+`mirror_run` for one
  case in the background, sends `SIGINT` after 1s (to the subshell PID and its direct child via `pkill -INT
  -P`), then compares `git status --porcelain -- bin/doctor.sh` before/after: both empty, unchanged.
  **Mutation-tested**: with the `$SCRIPT`-write reintroduced (same mutant as AC1), this test went red too
  (`FAIL AC4: SIGINT mid-recursion…`), i.e. it does catch the exact regression class under an actual
  interruption, not just in the steady state.
- AC5 (a future offending file becomes visible) — **chose the documentation route, not an in-suite guard**.
  Added a rule to `.claude/agents/shared/implementing-common.md` §9 ("Classes of cases and guards"), the
  file every `developer`/`qa-engineer`/`reviewer` reads at start. Reasoning: a reliable *automated* guard
  needs to tell "the real checkout source" apart from "a legitimate throwaway copy variable" by name/shape
  alone, and this very file is full of copy variables (`SCRIPT_SRC`, `$G/*.mut.sh`, `MUT_DOCTOR`) that a
  naive grep for "pointer var later used as a write target" would false-positive against; a semantically
  sound check would need to understand intent, which a shell/grep scan cannot do safely. The moment that
  matters is authoring time — before a future test file repeats the pattern — not a lagging post-commit
  scan, so the rule belongs where the agent reads it before writing the file. Did **not** duplicate it as an
  in-suite check for the same reason §3 of implementing-common.md gives against duplicating a rule: two
  copies diverge and cost a re-read on every launch.

## Deviations
- AC1 asks to sample "l'hash" — implemented as a direct `cmp -s "$SCRIPT" "$SCRIPT_SRC"` byte-for-byte
  compare instead of hashing. Same effect (any difference from the baseline copy is caught, with no hash
  collision surface at all), simpler, and no new hashing tool dependency (repo has no prior `shasum`/
  `sha256sum` usage to match).
- Touched `.claude/agents/shared/implementing-common.md` in addition to `bin/doctor.test.sh` (the task's
  **Files** line only names the latter). Justified by AC5 itself, which explicitly offers this as one of two
  valid options ("aggiungi il controllo dove gli altri test del repo lo leggerebbero, oppure scrivi la
  regola nel posto che un agente legge all'avvio. Una delle due, non entrambe.") — see AC5 above for why the
  in-suite guard was not chosen.
