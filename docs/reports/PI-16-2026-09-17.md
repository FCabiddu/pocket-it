# PI-16 — Writes become immutable fragments; the old files freeze; `retract`

**What changed.** `log`, `fact` and the new `retract` no longer write the old handoff files. Each invocation creates exactly one file `docs/handoff/{AAAA-MM}/{AAAAMMGGTHHMMSSZ}-{slug}-{rand4}.md` holding one `## Sezione` heading and one `- ` record, opened with `O_CREAT|O_EXCL`: no path is ever written twice, so two branches can never conflict on the memory (a merge is a union of added files). The old files are read for ever and written never. `retract "testo"` creates a `## Ritirati` fragment holding sha1[:12] of the text — it hides a fact from the composed view without touching the file that declared it. `where` prints the relative directory a write would use, needs no git repo, writes nothing (exit 0) — the verifiable signal that this version is installed. Dispatch, arity and per-argument checks stay in the single `SPEC`/`HANDLERS` declaration (the bash `case` is gone: it was a second subcommand list the sync assert could not see — PI-14 review), and `__spec X` now exits 2.

**Acceptance criteria → tests** (all in `bin/handoff.test.sh`, 355 assertions, all green):
- AC1 non-contention → the four-branch §11.2 scenario with `GIT_ATTR_NOSYSTEM=1`, an empty `.gitattributes`, a `--squash` merge and a further write; in-suite mutation (one shared file per branch) really does conflict.
- AC2 nothing written twice → 50 concurrent `log`s: 51 files, one entry each, every pre-existing file byte- and mtime-identical, plus the sibling proving ≥ 2 landed in the same second.
- AC3 freezing → writes on a repo with the old files leave `git diff` empty; on a repo without them, `docs/` holds nothing but `handoff/`.
- AC4 retract → a fact living in a frozen source *and* in another branch's fragment disappears from the view; both sources identical (hash + mtime); the new fragment holds the hash and never the text.
- AC5 cap → at 100 visible facts `fact` exits 3 naming `retract`; after a `retract` the same fact is accepted and the count is 100, not 101.
- AC6 real memory → on a copy of this repo's memory, `facts` and `recent --all` contain today's `awk` sets plus the new lines, with the §4.3 order.
- AC7 `where` → outside a repo, in a repo, with and without the old files: same output, exit 0, `git status --porcelain` identical; the pre-PI-16 stand-in leaves `?? docs/` and the test sees it red.
- AC8 texts → `git grep SESSION_HANDOFF` outside `docs|tech-analysis|tasks`: every surviving line describes a read-only frozen source, none says "prepends", "kept to 40", "creates docs/SESSION…" or "remove one line by hand"; `retro.md` prunes with `retract`.

**The three PI-40 properties, re-derived rather than re-run.** (1) `one_line()` still runs first, before the PI-39 date strip, and the order is now proved by its own test (a caller date followed by a newline). (2) Sections are still found by an anchored `^## ` heading — `split_section`. (3) The fixtures still come from the real writers: the 96-case writer × marker × shape grid drives the real `log`/`fact`/`retract` and asserts every pre-existing file is byte-identical while the one new file holds exactly one heading and one record. Hand-built fixtures survive only where no writer can reach the state (the over-cap frozen Log, a pinned timestamp, a frozen file) and say so in a comment.

**Deviations, all deliberate.**
1. **`HH:MM` in the log line (TAD §4.2) dropped.** Adding it would break the four anchored readers of `bin/retro-due.sh` (`MARK_RE`, `BUDGET_RE`, `STALL_RE`, `NEEDS_WORK_RE`), all `^- {DATE} ` immediately followed by the next token; sub-day order already comes from the filename stamp. Lines stay `- {AAAA-MM-GG} {testo}`.
2. **`O_EXCL` instead of `set -o noclobber`.** Same syscall flag; keeping the write in bash would have meant a second subcommand list, which the task's Notes forbid.
3. **Supersede rule (new).** A fragment that must supersede an existing source is stamped at least one second after it, so "strictly older" stays decidable at one-second resolution: without it `fact X; retract X` inside one second left X visible.
4. **Monotone suffix within one tree (new).** Same stamp + same slug ⇒ the suffix is chosen greater than the greatest sibling's, so a sequence of writes from one tree is causal and "most recent on top" is true; across branches (different slugs) concurrent writes stay unordered. Uniqueness still comes from `O_EXCL`, never from the suffix (mutation M1).
5. **`bin/retro-due.sh` touched, outside the `**Files**` list.** It recognised the composer by the bash `case` pattern PI-16 deletes, so it fell back to the frozen files and read every memory written after this task as empty — the retro would never come due. Its detector now knows both declaration forms; its unanchored-marker defect is untouched, that is PI-43.

**PI-43's home, decided deliberately: `bin/handoff_sections.py`** — `split_section`, `section_body`, `dash_lines`, `read_text`, `one_line`, with the threat model at the top. Loadable two ways with no copy: prepend-cat (`{ cat handoff_sections.py; cat; } | python3 -`, as `handoff.sh` does) or `import` (`sys.path.insert` — asserted by a test). A repo-wide test pins exactly one `def split_section(` and one `def one_line(`, so a second copy fails the suite.

**Two defects found in the suite's own shape, fixed here.** Assertions written as `producer | grep -q …`: under `set -o pipefail` grep exits at its first match and the producer dies of EPIPE, so a true assertion failed at random (1 run in 3 on AC2's 51-file snapshot). Every such pipeline is now a here-string, via `holds_lines` for containment. And `grep -qxF "- foo"` was parsing the pattern as an option — all now `grep -qxF -- "- foo"`.

Note that a log line carries the **local** date while its filename carries the **UTC** stamp, exactly as before PI-16.
