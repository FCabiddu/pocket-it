## Round 2 — reviewer findings (PR #48) and how each was closed

The reviewer executed the round-1 instructions verbatim and found four defects; I reproduced each independently in a scratch static page (outside this repo) before rewriting the instructions, and looked at every image produced.

1. **QA's measure didn't see clipped ink.** Built a container with `overflow: hidden` sized exactly to a `line-height: 0.7` Georgia heading: `scrollHeight === clientHeight` (declares clean) while the screenshot showed the descenders visibly sheared off. The reverse also reproduced: the same heading at `line-height: 0.8` in a taller box reported `scrollHeight > clientHeight` (false red) with the two screenshots pixel-identical to the eye. Replaced the rect/scroll comparison in `qa-engineer.md` with two ink-aware measures and tested both against the same page: `canvas.measureText().actualBoundingBoxAscent/Descent` vs the ancestor's content-box size predicted both cases correctly (clean case: ink 46.7px < 56px available → clean; clipped case: ink 46.7px > 33.6px available → clipped). The pixel-diff alternative (fixed padded region, `overflow`/`clip-path` lifted without touching height) also worked but needs a threshold — measured ~20 diff pixels out of ~39k on a genuinely clean render (anti-aliasing), so the instructions now say "an order of magnitude larger, in the shape of the clipped glyphs" rather than "any difference," and recommend the metrics method as the default because it has no threshold to tune.
2. **False reds on correct pages.** Added an explicit exclusion list to the same section: visually-hidden text, intentional `text-overflow: ellipsis`/`-webkit-line-clamp` truncation (distinguished from a mid-glyph vertical cut on an untruncated line), scrollable containers, marquees/tickers — plus "measure at rest" (fonts loaded, animations finished, reveals already fired), which closes the class the reviewer named (reveal masks pre/mid-animation) by construction.
3. **The designer's screenshot command didn't show the finished page.** Reproduced exactly: a test page with a fading-in hero (`opacity` entrance animation) and a below-the-fold `IntersectionObserver` reveal, shot with the round-1 command (`npx playwright screenshot --full-page "file://…"`). Result, seen with Read: the hero rendered at roughly 10% opacity (mid-fade) and the below-fold heading never appeared at all — full-page capture does not scroll the page in a way that fires scroll-linked observers before the shot. Also confirmed `file://` is a blocker in principle for `type="module"` scripts (documented, not independently forced to fail since the test page's script was inline-safe). Rewrote `ux-ui-designer.md` A.0 to: always serve locally (`python3 -m http.server`, never `file://`), and run a short Playwright script that waits `document.fonts.ready`, walks the full page top-to-bottom-to-top (so every `IntersectionObserver` reveal fires once) and waits `document.getAnimations()` to finish, before the full-page screenshot. Re-shot the same test page with this sequence: hero fully opaque, below-fold heading fully visible — both confirmed by looking at the resulting image. Added a browser-install retry (`npx playwright install chromium`) before the agent is allowed to declare "no browser available".
4. **Two conditions for when the QA check applies.** `qa-engineer.md` intro and the Step 4 bullet used different gates. Unified to one: "whenever the task under test touches the UI," independent of whether the project already has E2E/Playwright configured — if it does not, run a one-off `npx playwright` probe for this check alone (no new project dependency) and file a bug task if even the probe cannot run, instead of silently skipping.

Also corrected `tasks/PI-24-nobody-looks-at-the-rendered-app.md` Notes, which had proposed the rejected rect-comparison measure for AC3 — it now names the two valid measures (pixel diff, font metrics) and states why the rect/scroll comparison fails in both directions.
