# PI-24 — Nobody looks at the rendered app

## What changed and why
Two agent definitions edited so the pipeline gets an actual look at rendered pixels before judging them — the gap the goal describes (a source-only audit scored 5/5 the typography rules that were clipping titles; a11y/DOM checks never run layout).

**`.claude/agents/ux-ui-designer.md`, Mode A (audit):**
- New `A.0 — Render it before you score anything`: bring the target up (static file/folder → `file://` with Playwright, no server; a project with a dev/start/preview script → run it in background, poll until ready, then navigate; hosted URL → navigate directly), screenshot every key page full-page at ≥ 2 real widths (375×812 mobile, 1440×900 desktop; tablet only if the brief calls for it), **look at every screenshot with the Read tool before writing a single score**, stop any server started (by PID/port, never `pkill`/`killall`). If rendering is impossible, say so explicitly and cap Archetype & Typography at 3/5 — never 4–5 unseen.
- `A.1` now restricts scoring of dimensions 1 (Archetype & layout) and 2 (Typography) to what was seen in the A.0 screenshots, never source alone.
- `A.3` now opens the deliverable with a mandatory **Rendered** line (pages/widths seen, or the static-read-only admission and which dimensions are capped because of it).

**`.claude/agents/qa-engineer.md`:**
- Intro line now names the rendered-layout check alongside the a11y verification as covering wherever an E2E/browser surface exists, and states plainly what axe/DOM checks miss.
- Step 4 accessibility bullet gained a "What this does not catch" clause (colour/roles/ARIA, not glyph geometry; DOM tests never run layout).
- New **Rendered layout** bullet (mandatory, frontend, whenever the task touches the UI): measure each text node's real box (`getBoundingClientRect`/`scrollWidth`-`scrollHeight` vs `clientWidth`-`clientHeight`) against its clipping ancestor, at mobile **and** desktop viewports, failing on overflow in **either axis** (horizontal and vertical). Explicitly rejects a CSS-property/class assertion as insufficient — the note in the task file that such a check "stays green with the defect present".
