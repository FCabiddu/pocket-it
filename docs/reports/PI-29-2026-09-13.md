## Scope
The 4 findings from the reviewer's giro-3 comment on PR #60. All 4 closed.

## Finding 1 — rewritten base, `recover_cmd`
`bin/doctor.sh` §1b (the `is_ancestor` false branch): the printed command no longer builds a merge
commit and pushes it onto `refs/heads/{base}`. It now creates a local `rescue-{prev[:12]}` branch at
the lost commit and pushes **that branch alone** (`git fetch origin && git branch rescue-<sha12> <prev>
&& git push origin rescue-<sha12>`). The message says restoring `{base}` is a decision for a person,
not the script, and that doctor keeps reporting ERROR until the base is restored or, if the rewrite
was intentional, `--accept-base` is run. `has_prev` (checked one branch up, unchanged) already
guarantees `{prev}` is present locally before this code path is reached, so no command that could fail
on a pruned object is ever printed.

## Finding 2 — base branch deleted (normal run)
Same class, same fix: `err()` no longer prints `git push origin {prev}:refs/heads/{base}`. It now runs
its own `git cat-file -e {prev}^{commit}` check (this path had none before) and either prints the same
`git branch rescue-<sha12> <prev> && git push origin rescue-<sha12>` form, or, if the object is already
pruned locally, says so instead of a command that would fail.

## Finding 3 — base branch deleted, `--accept-base`
Identical change in the `accept_base` branch's `status == "deleted"` case: same `cat-file` guard, same
rescue-branch message, "nothing to accept" kept for the message's opening (still true — there is
nothing for `--accept-base` to accept when the base was deleted, only unrelated to a rewrite).

## Finding 4 — `doctor.test.sh` reversed to the new contract
Replaced the round-3 recovery block. For each of the three printed commands (rewrite/normal,
delete/normal, delete/`--accept-base`) the test now, on its own fresh origin+clone:
- extracts the command from doctor's own output (new `extract_save_cmd*` helpers, regex updated to the
  new message wording),
- runs it as printed and asserts `git ls-remote origin refs/heads/main` is byte-identical before/after,
- asserts a `rescue-<sha12>` branch is pushed to origin pointing at the lost commit,
- asserts doctor stays RED afterwards (green only once `--accept-base` is also run, for the rewrite
  case; the base literally doesn't exist in the delete case so there is no green path without a human
  restoring it),
- asserts the exact command, passed as a `{"tool_input":{"command":...}}` PreToolUse payload to the
  real `.claude/hooks/guard.sh`, exits 0 — even with `base=main`.
A mutation reverting each printed command to a direct `refs/heads/main` write (fast-forward via a
`commit-tree` merge for the rewrite case, a plain push for the delete case, since the base doesn't
exist yet there) proves the "identical before/after" checks are not vacuous, and that the same mutated
command is blocked by the real guard (exit 2).
