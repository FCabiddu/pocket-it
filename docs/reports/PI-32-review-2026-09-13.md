### Finding

**1. `.claude/hooks/guard.sh` `Lexer.param()`: un `${…}` dentro il valore lo lascia classificato come dato, ma la shell che esegue il comando lo può valutare.** Regola: il commento TEXT OPTIONS dice che il prezzo torna «a un falso positivo, mai a un push mancato». Qui invece si perde un push. Claude Code esegue i comandi nella `$SHELL` dell'utente, che su questa macchina è `/bin/zsh`.
- Prova della shell: `zsh -c 'echo "A:${(e)x:-\$(echo RAN)}"'` stampa `A:RAN`. Il flag `(e)` esegue la sostituzione scritta con `\$`.
- Verdetti della guardia, da agente (`agent_id` presente):
  - `git commit -m "${(e)x:-\$(git push origin main)}"`: giro 2 ALLOW, giro 1 (`18cb6b3`) BLOCK
  - `gh pr comment 54 --body "${(e)x:-\$(git push origin main)}"`: giro 2 ALLOW, giro 1 BLOCK
  - `git commit -m "${(e)x:-\$(gh pr merge 8)}"`: giro 2 ALLOW, giro 1 BLOCK
- In bash 5 la stessa classe passa da `${x@P}` e dai subscript aritmetici `${a[…]}`.
- Correzione: in `param()` un qualsiasi `${…}` rende il valore codice (`code = True`), quindi il valore non si sostituisce.
- Righe di test nei due versi:
  - BLOCK: i tre comandi sopra
  - ALLOW: lo stesso messaggio senza `${`
- Nel report, la mutazione «`param()` torna `code` falso» deve rendere rosse le righe BLOCK.

**2. `.claude/hooks/guard.sh` `spans_of()`: il valore sostituito con `TEXT` può essere rieseguito da un comando successivo della stessa riga.** Regola: come sopra, un push che il giro 1 bloccava ora passa.
- Prova della shell: `zsh -c 'true "echo RAN"; eval "$_"'` stampa `RAN`.
- Verdetti, da agente, giro 2 ALLOW e giro 1 BLOCK:
  - `git commit -m "git push origin main"; eval "$_"`
  - `gh pr create --title "git push origin main" --body x; bash -c "$_"`
  - `gh pr comment 1 --body "gh pr merge 8"; eval "$_"`
- Stessa classe, da coprire: `git commit -m "git push origin main" && git log -1 --format=%s | sh`.
- Correzione: nessuna sostituzione, cioè si legge il comando intero come prima, quando fuori dagli span sostituiti c'è una di queste cose:
  - la parola `eval`, `source`, `.`, `fc` o `exec`
  - una shell (`sh`/`bash`/`zsh`/`dash`/`ksh`, anche per path) come comando o dopo un `|`
  - `xargs`
  - `$_`, `${_}` o `!$`
- Per queste forme il prezzo torna a un falso positivo, come dichiarato. Servono righe BLOCK per i quattro comandi e ALLOW per gli stessi senza la parte che riesegue. Aggiorna anche la sezione Residue del commento in cima.
