# PI-13 — guard fail-open on any assignment/prefix in front of `git push`

## Defect
The push classifier in `.claude/hooks/guard.sh` anchored on `git` at the start of each
segment, so anything in front of `git` made it miss and the command was never classified —
the guard did not deny, it did not see. Fail-open spellings that reached the base branch:
a leading variable/`env` assignment (`FOO=bar git push`), the one-off-config form
(`git -c k=v push`), the audit prefix with a NON-authorized value (`=0`/`=2`, a form
declaring itself unauthorized yet disarming the check), plus two same-bucket forms that
reach the base without naming it — a glob refspec and `--all`.

## Fix (`.claude/hooks/guard.sh`)
- Gate fires whenever the stripped command has `git` and `push` as bare words; the
  classifier returns empty (ALLOW) for non-push git commands, and STR/heredoc stripping
  still keeps a mere mention out of it.
- Replaced the `^git` regex with a tokenized parse that strips leading `env`/`NAME=VALUE`
  prefixes (audit prefix included, any value) then consumes git globals, enumerating the
  value-taking ones (`-c -C --namespace --git-dir --work-tree --exec-path --super-prefix
  --config-env`) so a config value is never read as the subcommand. Authorization stays in
  the shell by EXACT equality on `=1`; the parser only classifies the target.
- `--all` and glob-destination refspecs are treated as base-reaching (`is_glob` +
  `fnmatch`-based `targets_base`, so `refs/heads/*` matches main while `refs/heads/task/*`
  does not — task cleanup keeps passing).
- Classifier is fed the RAW command, so a quoted glob refspec is seen, not collapsed to STR.

## Tests <-> criteria (`.claude/hooks/guard.test.sh`, new PI-13 section, 113/113 ok)
One+ case per AC: AC1 var/env prefix; AC2 `-c` forms; AC3 `=0/=2/=10`; AC4 exact `=1` passes,
prefixed force still blocks; AC5 same spellings to a feature branch pass; AC6 glob quoted &
unquoted, `+`/plain/single-ref; AC7 `--all` with force and bare; AC8 task cleanup in the same
spellings; controls (`git config push.default`, `git log`) that mention push but are not one.

`targets_base` equality-only → AC6 red; `has_all=False` → AC7 red.
