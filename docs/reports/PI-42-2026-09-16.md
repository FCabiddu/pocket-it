# PI-42 — doctor must check the TAD sections the board actually cites

## What changed and why
`bin/doctor.sh` §4b warned against a hardcoded `expected = {"5.2","6.2","7.6","8.1","9.3","11.1"}`
subsection set, regardless of whether any task cited those numbers, and regardless of which document
(project TAD vs. a feature delta) a citation actually named. A valid TAD numbered differently warned
forever with no way to clear it, and a section cited only in a delta was checked against the wrong file.

Replaced with a derivation pass: for every task file, read its `**TAD**:` line, split it into
qualifier segments (on U+00B7 `·`), resolve each segment's document, extract every `§N[.N]` citation
in it, and warn only when a citation resolves to a missing document or a missing heading in the
document it names. The pre-existing top-level order check (`## N.` ascending) is untouched — same
loop, same wording, moved above the new block, marked `# PI-42 CHECK BEGIN/END` around the new logic
only so a mutation test can restore the old block in isolation.

## Citation forms found (AC2)
Derived by reading `implementation-planner.md`'s own template plus every `**TAD**:` line in this
repo's own `tasks/*.md` (`grep -rn '^\*\*TAD\*\*:' tasks/`), not assumed:
- `none` / `none — {reason}` — nothing cited.
- Unqualified: `§5.2 (endpoints), §4.3 (schema), §8.2 (patterns)` — no document named; resolves
  against `tech-analysis/PROJECT_TECH_ANALYSIS.md` if it exists, else the single classic
  `tech-analysis/*_TECH_ANALYSIS.md` if there is exactly one.
- Keyword-qualified, segments joined by U+00B7: `PROJECT §3, §8.2 · DELTA §5.2` — `PROJECT` resolves
  to the project TAD, `DELTA` to `tech-analysis/*_TECH_DELTA.md`.
- Document named directly by path, sections in parens: `tech-analysis/{NAME}_TECH_ANALYSIS.md
  (§2.3, §4.4, §12 PI-17, §13 R-03)` — this repo's own real board's actual convention, distinct from
  both spellings the task text names; resolves against exactly that path.
A dot in the cited number selects a subsection heading (`### N.N`); no dot selects a top-level one
(`## N.`), so `§12`/`§13` (this repo's own real usage) are checked correctly as top-level sections.
