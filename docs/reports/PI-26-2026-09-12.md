# PI-26 — 2026-09-12

## What changed and why
`bin/next-wave.sh`'s risk→model mapping used to look like a decision the script made. It renamed the
JSON field `model` to `model_hint` (same "opus for Risk: high, sonnet otherwise" computation, now
documented in a comment as a starting suggestion). `run-wave/SKILL.md` and `quickfix/SKILL.md` were
updated so the orchestrator's launch step says explicitly that it picks the model per launch and states
the reason in one line — `model_hint` / `Risk` is a suggestion, never the input to a fixed rule. Both
skills and `CLAUDE.md` (Conventions table, new "Model choice" row) now carry the same written criteria:
bigger model for irreversible/destructive work, security or permission boundaries, open-ended reasoning
(diagnosis, design, root-cause analysis and their review), a wide surface to keep coherent; smaller
model for mechanical, well-specified or prose-only work. The same paragraph restates the two invariants
from the task's Goal: the frontmatter `model` stays as the floor (no subagent has a default model, so an
unset one inherits the session's, the priciest), and the model is never raised as a reaction to a failed
round on its own — only if the analysis names it as the cause.

Stale mentions of the old mechanism in `CLAUDE.md` (pipeline diagram, roster row for `developer.md`,
`/run-wave` and `next-wave.sh` script-table rows) were updated to point at the new "Model choice" row
instead of restating "opus if risk high".
