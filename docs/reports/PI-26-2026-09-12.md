# PI-26 — 2026-09-12

## What changed and why
`bin/next-wave.sh`'s risk→model mapping used to look like a decision the script made. It renamed the
JSON field `model` to `model_hint` (same "opus for Risk: high, sonnet otherwise" computation, now
documented in a comment as a starting suggestion). `run-wave/SKILL.md` and `quickfix/SKILL.md` were
updated so the orchestrator's launch step says explicitly that it picks the model per launch and states
the reason in one line — `model_hint` / `Risk` is a suggestion, never the input to a fixed rule. Both
skills and `CLAUDE.md` (Conventions table, new "Model choice" row) now carry the same written criteria:
bigger model for irreversible/destructive work, security or permission boundaries, open-ended reasoning
(diagnosis, design, root-cause analysis and their review), a wide surface to keep coherent; smaller
model for mechanical, well-specified or prose-only work. The same paragraph restates the two invariants
from the task's Goal: the frontmatter `model` stays as the floor (no subagent has a default model, so an
unset one inherits the session's, the priciest), and the model is never raised as a reaction to a failed
round on its own — only if the analysis names it as the cause.

Stale mentions of the old mechanism in `CLAUDE.md` (pipeline diagram, roster row for `developer.md`,
`/run-wave` and `next-wave.sh` script-table rows) were updated to point at the new "Model choice" row
instead of restating "opus if risk high".

## Follow-up round: `Files` was incomplete, completed in the same PR
The first pass respected the task's `**Files**` list exactly, but that list itself did not cover every
place carrying the old rule — a planner gap, not a developer scoping choice. Before sending the PR to
review, ran a second, wider search with several phrasings (`opus (if|when|only|for)`, `risk high …
opus`, `model … (by|from|per) risk`, `risk … (decides|drives|determines|sets|picks|runs) … model`,
`stronger model` / `bigger model` near `risk`) across every `.md`/`.sh`/`.py` file, not just the
originally-cited ones. Found two more live readers of the old rule and added both to `**Files**`:
- `README.md` — the pipeline diagram (`opus if Risk: high`) and the `/run-wave` skill-table row (`Opus
  for high risk`) both stated the mapping as fact. Reworded to "model chosen per launch" / "not by
  `Risk` alone".
- `.claude/agents/implementation-planner.md` — told the planner "The orchestrator runs high-risk tasks
  on the stronger model", i.e. the same fixed rule from the other side (why `Risk` matters). Reworded to
  say `Risk` feeds `next-wave.sh`'s `model_hint`, a suggestion, and points at this repo's own "Model
  choice" criteria for the actual decision; kept the "keep the flag honest" advice since `Risk` still
  matters as an input.

Deliberately **not** changed: `docs/agent-reviews/PIPELINE-V2-2026-09-06.md` — a dated audit/changelog
entry recording what changed on 2026-09-06 ("`Risk: high` runs on Opus" as that day's fix). It is a
historical record no agent reads at runtime for behaviour, not a live spec; rewriting it would falsify
what was actually decided that day. `bin/next-wave.sh`'s own risk→hint computation and its description
as a "starting suggestion" in the two skills and `CLAUDE.md` are the intended remaining mentions, not
leftovers.
