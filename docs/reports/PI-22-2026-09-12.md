## What changed and why
- **Defect A** (`bin/cleanup-merged.sh`). `merged_into()` used `merge-base --is-ancestor`. A branch created from a base with no commits yet is an ancestor of it, so it counted as merged and its worktree and branch were deleted. The new `base_line()` keeps any branch whose tip is on the **first-parent line** of a base (skipping the branch itself, for `--all`). Merge commits, squashes and rebases never put a branch's own commits there. It runs first in `decide()`, which now also prints the reason for keeping (`no commits of its own: tip is on the first-parent line of origin/main`).
- **Same class, same function.** (1) A merged PR removes the worktree only if its `headRefOid` contains the local tip. Before, commits made after a squash merge were deleted. (2) A failing `git status` means keep, where it used to count as clean. (3) The dirty check runs before any merge test, which also skips a `gh` call.
- **Defect B** (`.claude/agents/shared/implementing-common.md` §5). New paragraph, "Worktree gone — stop, never fall back": `cd <wt> && …` on every command. The worktree counts as lost when the path is missing, the toplevel differs or the branch differs. Then stop and report. It forbids recreating the worktree and continuing in the main checkout or any other directory, including for `handoff.sh`. Same file: the worktree-path example also named a real project, now replaced with `<project>` (§7b).
