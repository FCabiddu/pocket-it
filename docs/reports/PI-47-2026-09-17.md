# PI-47 — the bare `<pm> <token>` form must not clear a token that is also a script
**Branch**: task/pi-47-bare-form-clears-scripts · **Files**: bin/verify.sh, bin/verify.test.sh

**Defect, re-measured first:** against a base declaring no scripts, `base_blockers` cleared `npm pack`,
`publish`, `version`, `update` (`npm run pack` refused) — so the base re-run counted as a comparable check and
a red the branch owns could be reported as exit 3, "inherited": a wrong green.

**Rule, and the evidence it rests on (AC2).** The token is a script or the manager's own verb; its spelling
carries neither. The **manager** decides, from the **package.json of the tree it runs in**, by a precedence
rule that differs per manager and per version (npm runs its own `version` verb, yet runs `test`/`start`/
`stop`/`restart` bare; pnpm/yarn/bun accept `<pm> <script>` generally). This script must not learn that rule —
encoding it is a word list again, and a word list is what cannot tell the two apart. What is establishable
without it: **if the two trees agree on whether that script is declared, the manager — whichever rule it
applies — picks the same side on both runs**, so the base re-run is the same check. The evidence is two
package.json files, never the token: the base's (`has`, as rule 2 already did) and the branch's
(`has_at "$WT_REAL"` — the worktree rule 4 already reads, still on disk when the base re-runs, verify.sh:342).
`$pmsub` is consulted **only** in the "neither declares" cell, so removing a word cannot re-open this hole.

**Forced case, and which way it goes (AC3):** branch declares a `version` script, base does not, `version` is
also a verb. npm would run its verb on both sides (clearance right); pnpm/yarn/bun may run the branch's script
against the base's verb (clearance = wrong exit 3). Two defensible readings, no evidence left → **blocker**: a
wrong exit 3 tells a developer their branch is fine when it is not; an extra blocker costs one re-run. The
mirrored cell (base declares, branch does not) is the same disagreement and blocks too — also new, deliberate.
