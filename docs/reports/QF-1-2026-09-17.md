# QF-1 — A cause found inside an approval must raise a signal too

**Branch**: `task/qf-1-cause-inside-approval` · **Label**: DevOps · **Risk**: high · **Budget**: 120

## What changed and why
`retro-due.sh` asked the cause field only of lines its `NEEDS_WORK_RE` anchor had already matched, so a
defect found and named inside an APPROVAL raised nothing and the learning loop silently disarmed itself.
The fix is structural, not a widening of the anchor: `extract_cause()` is now applied to **every** log
line, and `NEEDS_WORK_RE` survives untouched, used for two things only — counting review ROUNDS (signal c,
`repeat-needs-work`) and choosing the provenance label of the cause signal (`needs-work-cause` on a round,
the new `cause` elsewhere). That is the whole point: the three defects this recogniser has already been
rewritten for all lived in the outcome anchor, and the cause path no longer passes through it.

- `bin/retro-due.sh` — cause read per line; new `cause` signal type; header `:8-40` rewritten to state the
  outcome-blind rule, the over-fire/under-fire asymmetry, and what QF-1 did **not** relax.
- `.claude/agents/reviewer.md` — `false-coverage-evidence` added to the taxonomy (Step 0, NEEDS WORK
  template, Step 6 report line); the naming duty extended to "every finding you report inside an APPROVAL";
  new paragraph "A cause is a property of the finding, not of the verdict"; APPROVED log template gains an
  optional ` — cause: …` with the explicit rule that it is **absent** when there is nothing to name — never
  `first-round`, never empty.
- `bin/retro-due.test.sh` — 80 → **119** `ok`, all green.

## Ambiguity I am not resolving silently
A log line whose **free text** literally contains ` — cause: X — ` (a PR title, a quoted finding) is
indistinguishable from a real cause field by the line alone. I took the louder reading: it fires. Under-
firing disarms the loop; a spurious signal costs one retro paragraph. If this ever bites, the fix is a
field position rule in `handoff.sh log` (out of scope here, and that file is owned by another agent).
Consequence for me: my own handoff line for QF-1 must not contain a `— cause:` field.
