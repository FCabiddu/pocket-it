## What changed and why
`bin/handoff.sh log` truncated the `## Log` section to the last 40 lines with
`lines=lines[:40]`, silently discarding the overflow — a project's narrative
memory that erases without a trace. Rotation now moves the pushed-out lines
to a new `docs/SESSION_HANDOFF_ARCHIVE.md`, append-only (never overwritten,
never re-created if it already exists), and the command reports how many
lines it archived on stdout. The 40-line cap on the live log is unchanged;
only the destination of the overflow changed, matching the refuse-don't-drop
rule already used for the facts cap (PI-2/PI-5).

## Fix round — review findings (PR #30, NEEDS WORK)

**Finding 1** — the archive read oldest-at-bottom *within* a batch (log order
kept) but oldest-at-top *across* batches (each new batch appended below the
last), and the header (line 8) documented only the within-batch axis. Fixed
by reversing each evicted batch before writing it: `f.write("\n".join(reversed(overflow))+"\n")`.
Since batches are always appended in the order they rotate, the whole
archive file now reads oldest-at-top, newest-at-bottom, top to bottom, no
exceptions — one order, not two. Line 8 and the archive's own header text
now say exactly that.

**Finding 2** — `LOGCAP` was introduced but the python fallback that adds a
missing `## Log` section (triggered when a file has no such section yet)
still spelled out `ultime 40 righe` by hand. Interpolated `{logcap}` there.
Also found, by the same reasoning ("no point in the script should repeat
the number by hand"), that the heredoc creating a brand-new
`SESSION_HANDOFF.md` had the identical hardcode; switched it from a quoted
(`<<'EOF'`) to an unquoted (`<<EOF`) heredoc with the one backtick escaped,
so `$LOGCAP` interpolates there too. `LOGCAP=40` (line 13) is now the only
place the number is assigned; every place it is printed reads the variable.

Tests added in `bin/handoff.test.sh`, both proven by mutation (reverted the
fix, watched the specific new assertion go red, restored the fix, watched
it go green again — not inferred, run three times each):
- Order (finding 1): hand-built a 45-line log so one rotation evicts 6 lines
  at once (the only way to see within-batch order). Asserts the oldest of
  the batch is on top, the newest-of-the-evicted is at the bottom, and a
  second rotation's line lands *below* the first batch while the
  oldest-ever entry stays on top. Mutation: dropping `reversed()` turns the
  three order assertions red; not the pass/count ones.
- Hardcode (finding 2): a behavioural case for each of the two write sites
  (fresh file via heredoc; existing file lacking a `## Log` section via the
  python fallback) asserting the header shows the live cap and, for the
  heredoc path, that no literal `$LOGCAP` leaked into the file (a quoting
  regression would do that since the fix depends on the heredoc being
  unquoted). Plus a structural guard — `grep` on `bin/handoff.sh` itself —
  that the fallback line builds the number from `{logcap}` and never spells
  out `40`. Mutation: reverting the interpolation to a literal `40` turns
  the structural guard (and the F2b behavioural case, once the file text
  no longer matches) red.
